## 0. 一句话结论

客户端是一个**非权威的薄前端**：网络层信任服务器给的分帧/加密，但它发出的每个请求都携带"特权意图"，唯一能安全拒绝的地方只有服务器。**所有 command id、payload 字段（userId、档位索引、tableName/value、SubType、URL）、以及客户端自述的标志位（DevMode、IsInnerPackage、checkCode、CmdIndex、SID、region）都必须当作攻击者可控**——因为它们全都本地可伪造，而传输层没有真正的逐包认证（单字节 XOR，密钥就在明文包头里；生产走 TLS，所以那点加密是"隧道内混淆"，不是安全边界）。

最高危的是**两个只在客户端做门禁的 GM/QA 协议命令**——它们是游戏协议帧，改包客户端无视任何客户端门禁照发不误，拦截点只能在服务端：

- **cmd 98765**（SYS_TEST_CMD）：免费发货 + 通用反射派发 `command.QaOperate`，且 userId 取自包体。
- **cmd 91001**（SYS_HEIDISQL_CHANGE）：用硬编码的 `g10read`/`g10read` 对 `user_data` 表做任意增删改查。

紧随其后是玩家生态完整性：**聊天 SubType==87 让对端 JSON 灌进 string.Format 崩掉每个接收者**（远程崩全服），以及**领奖类命令只发客户端自选档位、无消费证明**。

### 证伪 / 降级（旧审计或原始发现被夸大之处）

- **H2 传输加密：HIGH → MEDIUM**。生产传输是 `wss://`（TLS），明文 `ws://` 只在 `DevMode && !DevUseDomain` 下出现（`DotnetWebSocket.cs:162-164`）。对网络中间人，TLS 已提供真正的机密性/完整性；字节 XOR 只是隧道内混淆。只有"客户端即攻击者"模型下才完全成立——而那本就是任何薄客户端的标准姿态。
- **H1 收包长度 DoS：拆分并降级**。入站帧长 DoS（rank 14）是**纯客户端自伤**（HIGH→LOW），且"重连风暴"说法**证伪**——异常路径绕过 `OnSocketError`，是静默把 worker 弄挂而非循环。zlib 解压 DoS（rank 11）和无逐包异常隔离（rank 12）真实但属客户端可用性（HIGH→MEDIUM）。真正高价值的是**对称推断出的服务端 OOM**，客户端树里看不到。"卡到 3000ms 超时"的触发描述不准。
- **M2 SID 熵：MEDIUM → LOW**。它是握手前的引导值，服务器随即用 pkg 98888/96666 覆盖；且"XOR 混淆"说法纠正为**明文**（偏移 12–43，在 57 字节编码边界之前）。
- **H5 DevMode/后门：HIGH → MEDIUM/LOW**。GM 口令（rank 8）、DevMode 本地写（rank 18）、`_game_config0.json`（rank 19）都是**客户端本地重配置，本身不换取任何服务端认可的特权**。原始发现里"IsInnerPackageDebugMode 门禁 cmd 98765"的说法**证伪**（其真实用途是支付证书/SDK登录/版本串，不碰 98765 的发送）。
- **H3 runtimeconfig.json（rank 20）：HIGH → LOW/客户端本地**。哈希表只做 diff 检测、从不发给服务器；真正的远程真实性门禁在原生管线（不在托管代码范围）。
- **敏感词过滤（rank 23）：MEDIUM → INFO**。接收端只是显示层、无服务端信任边界；服务端审核才是真正的控制。
- **昵称非平衡花括号崩溃：整条证伪**。名字/UserName 永远是 `string.Format` 的**参数**、从不是格式串，无法破坏占位符解析。

## 2. 分级漏洞清单

### 🔴 严重

#### #1 cmd 98765（SYS_TEST_CMD）—— 免费发货 + 反射 QaOperate，userId 取自包体

- **证据**：`Game.Network/Tenth.Network/NetCommandDef.cs:621` `SYS_TEST_CMD_98765 = 98765`；`Game/Tenth.GMTools/Commands.cs:7203` `Send<object[]>(98765, new object[2]{120, new object[4]{"command.QaOperate","addAllHeroExp", userId, exp}})`，其中 `userId = UserData.UserId` 是包体字段；`PayData.cs:1216/1258` `Send(98765, [11,[good_id]])` 走免费发货回调 `OnInnerBuyGoodsCallback`。
- **攻击者能做什么**：改包/构包客户端（checkCode 自算）任意发 98765 → 给自己或**别的 userId** 加英雄经验/体力、清 CD、跑 QA 操作、拿货却无付费订单。
- **服务端必须**：生产环境**硬禁 98765**，或只接受服务端认证过的 GM 账号白名单；绝不把 `[11,[good_id]]` 当已付款订单（要求校验过的 SDK 支付回调）；绝不向游戏协议暴露 `command.*` 反射派发；**忽略包体 userId，只按已认证会话身份行事**。

### 🟠 高危

#### #2 cmd 91001（SYS_HEIDISQL_CHANGE）—— 硬编码 g10read 认证的任意表增删改查

- **证据**：`NetCommandDef.cs:215` `SYS_HEIDISQL_CHANGE = 91001`；`Game.UI.GamePlay.Core/Tenth.UI/ModifySqlDataUI.cs:110` `string text2 = "g10read"; string text3 = "g10read";`，随后组包 `[g10read, g10read, tableName, num=2(UPDATE), primaryKey, headStr, content]` 并 `Send<List<object>>(91001, obj, ...)`（:122）。
- **攻击者能做什么**：任何人从二进制里抠出这两个常量，构造 91001 帧携带任意 `tableName/key/column/value`，对 `user_data` 行做读/UPDATE(2)/INSERT(1)/DELETE(3)——**若服务器认这个字面量就是跨账号改档**。
- **服务端必须**：生产禁用 91001，或限定服务端认证的 GM 身份 + 按账号 RBAC + 审计日志；**绝不把常量 `g10read` 当授权**；绝不向任何游戏客户端暴露原始表/列/值 CRUD。

#### #3 聊天 SubType==87 → string.Format 远程崩全服

- **证据**：`Game.Data.GamePlay/Tenth.Data/ChatDefine.cs:2453` `flag3 = (val2.SubType == 87)`；:2455 `if ((!string.IsNullOrEmpty(text) && flag && flag2) || flag3)` —— **`SubType==87` 用 `|| flag3` 绕过其它门禁**；:2499 `text = string.Format(text2, val5.ToArray())`，`val5` 攻击者可控、无 arity/类型校验。
- **攻击者能做什么**：能让 `SubType=87` 被转发的玩家/对端，发一条精心构造的 Content JSON（数组过短、元素类型错），在**每个渲染该频道的客户端**触发 `FormatException`/`IndexOutOfRange`/`InvalidCast`——一条消息崩一片，业务级"核弹"。`NetObserver` 会重抛，上游无 catch。
- **服务端必须**：**绝不转发客户端自选的 SubType/PushLog id**——PushLog 只能服务端产生，入站玩家聊天强制为纯文本子类型；服务端组 PushLog 时校验参数个数/类型与模板占位符完全匹配再广播。

#### #4 热更核心补丁（含 Game.Minimal.dll）下载→解压落盘→重启加载，无签名/真实性校验

- **证据**：`Game/Tenth.Update/PatchDownloadHandler.cs:106` 补丁项只解析 ver/size/url（无 hash/签名）；:168 `CCUtil.uncompress(text2, docDir, listOutputPath)` 解压进可写文档目录；:235 `CheckPatchContainsAssemblyMinimalDll → OnProcessFinish(true, "Assembly/Game.Minimal.dll")`。整个 `Tenth.Update` 无 RSA/ECDSA/Verify。
- **攻击者能做什么**：被污染的 CDN/patchlist 或 MITM（或 root 设备上的本地改包者）注入任意托管代码，客户端下次重启加载。本地改包者稳成；纯网络需击穿 TLS。
- **服务端必须**：把客户端的二进制/版本/反作弊自证一律当攻击者可控、所有玩法服务端重校验。客户端加固：每个补丁包用非对称签名（pin 公钥），**解压前、加载任何 DLL 前**验签——TLS 不够。

#### #5 实名/学信 KYC WebView 加载服务器给的 verify_page_url 且注入服务器给的 js_patch_url 作为 customJS

- **证据**：`Game.UI.GamePlay.Activity/Tenth.UI/ActivityCampusAuthenticationMainUI.cs:155` `string customJS = (string)packet["js_patch_url"]`；:156 `OpenWebView(packet["verify_page_url"], ..., customJS)`；在 `PlatformBeforeLoad.cs:483` 原样透传 `val2["customJS"] = customJS`。无 host 白名单、无固定脚本约束。（复核：sink 与可达性确证；原生 customJS 执行语义无法从托管代码 100% 证实，故列高危而非严重。）
- **服务端必须**：把 `verify_page_url` 限定到固定官方验证域（host 白名单 + https）；**绝不下发 JS 体/URL 作为 customJS**——customJS 只能是内置固定脚本；生产环境从响应里删掉 `js_patch_url`。

### 🟡 中危

- **#6 领奖类命令只发客户端自选档位（cmd 351 充值继承带客户端 Level，无消费证明）** — `ActivityRechargeInheritanceMainUI.cs:536` `Send<int[][]>(351, new int[1][]{ new int[1]{ rechargeRewardInfo.Level } })`，资格列表在 :452 客户端自建（`if (current.Status == 1)`）。**服务端必须**按权威累计充值独立计算档位资格、领取次数、时间窗，拒绝超出已赚状态的客户端档位。（证实链 B）
- **#7 邮件驱动 WebView 把 FULL_UIN/角色标识/GM token 拼到邮件给的 URL host** — `MailSingleDetailPanel.cs:1593` `url2 = url + "?token=" + val["token"]`；:1541 拼 `?uid={FULL_UIN}&role_id=...`，host 来自邮件、无域白名单。**服务端必须**对每封邮件 Url 强制官方域白名单；绝不把 FULL_UIN/GM token/角色 id 放进未 pin 的 host 查询串。（复核：账号接管框架降级——GM token 作用域未证实，泄露的是 PII 非凭证）
- **#8 硬编码 GM 口令 `g10#debug` + 固定手势在正式包打开 GM 配置面板** — `GmEntryView.cs:37` `if (editBox.GetText() == "g10#debug") { ...; GmConfigView.ShowPanel(); }`；解锁手势 `GM_EXPECTING_TOKENS=[1,-1,-1,1,1,1,-1,-1]`（`LoginMainUI.cs:4905`）**未受 DevMode 门禁**。动作是客户端本地（切服务器 IP/端口、翻 DevMode），但泄露开发基础设施、且能把客户端重定向到流氓服务器。**服务端必须**把客户端选的服务器/登录端点当不可信，会话绑服务端签发 token；不信任任何客户端自述 GMSdkMode/DevMode。客户端加固：正式包剥掉口令/手势/面板。（证实 H5，服务端信任框架降级）
- **#9 登录公告等服务器/配置来源 URL 无域白名单直开 WebView（钓鱼）** — `LoginBulletListUI.cs:421` `OpenWebView(linkUrl.Substring(1))`；:680 从 `;` 分隔的公告 url 开 WebView，sink 无 scheme/domain 校验，且在未 pin 的登录前通道。**服务端必须**把公告链接/图片 URL 服务端限定官方域白名单。（证实 M3/链 H）
- **#10 传输"加密"是单字节 XOR、密钥在明文包头；checkCode 是无密钥线性校验和非 MAC；无防重放** — `DotnetBaseSocket.cs:323` `int num3 = (CmdIndex*13) ^ CmdId ^ UserId`；:334 `SetEncodeSeed((byte)num3, 57)`；`NetBuff.cs:79` `mBody[i] ^= mEncodeSeed`；下行常量 0x98。**服务端必须**绝不把 num3/checkCode 当认证、CmdIndex/SID 当防重放；会话绑服务端签发短期 token，按已认证身份授权每个字段。（证实 H2，生产 TLS 故降级）
- **#11 zlib DataType==3 解压输出缓冲按未校验的服务端声明有符号长度分配（客户端分配型 DoS）** — `DotnetBaseSocket.cs:556` `byte[] array2 = new byte[netBuff.ReadInt()]`，`ReadInt` 有符号大端无 clamp。**反向教训**：对称的服务端解析器（H1/链 D）必须在 `new byte[]` 前校验 `0 < declaredLen <= MAX`，防恶意上行 OOM。
- **#12 无逐包异常隔离——一个畸形入站包让接收 worker 出错→静默断连+重连循环** — `DotnetBaseSocket.cs:675` `ProcessBytesReceived(msgBytes)` 无 try/catch；worker 外层 catch（`DotnetSocketReceiveChannelBase.cs:99`）只 SetException 返回。客户端修复：逐包 try/catch，丢单帧不挂 worker。

### 🟢 低危（客户端本地 / 信息泄露 / 架构留白）

- **#13** 无防重放：序号是明文自增 `CmdIndex`（`DotnetCmdMgr.cs:217`），抓包可原样重放。→ 服务端按会话单调序号窗 + 时间窗。（证实 H2）

- **#17** GM WebView 把活 GM token 拼到未 pin 的邮件 URL（reason 'JL'，`PlatformBeforeLoad.cs:872`），同 #7 类。（证实 L1）
- **#18** DevMode 是本地可写 UserDefault 布尔（`GameConfig.cs:289` 读 `_Key_Dev_Mode_`），横向解锁客户端 GM/调试面；但**本身不换取服务端特权**。**"98765 门禁"链证伪**。→ 服务端按真实账号角色授权 GM 通道，独立于客户端标志。（H5 降级）
- **#19** `_game_config0.json` 探测翻转 IsInnerPackage，让投放/覆盖的配置改写 DevMode/ServerIp/UpdateAddress（`GameConfig.cs:881/936`），内网构建机制、非服务端认可的提权。（H5，客户端本地）
- **#20** `runtimeconfig.json` 程序集哈希只做 diff 检测非真实性（`MonoLoader/MonoLoader/PluginLoader.cs:781`），且配置无签名在可写路径；从不发给服务器。（H3 降级为客户端本地）

## 3. 服务端加固优先级（按 ROI 排序）

1. **cmd 98765（SYS_TEST_CMD）**：生产直接拒绝，或只接服务端认证的 GM 白名单。绝不把 `[11,[good_id]]` 当已付款订单（要求校验过的 SDK 支付回调）；绝不暴露 `command.*` 反射派发；**忽略包体 userId，只按已认证会话身份**（防跨账号 QA 操作）。
2. **cmd 91001（SYS_HEIDISQL_CHANGE）**：生产禁用，或限服务端认证 GM 身份 + 按账号 RBAC + 审计。绝不认硬编码 `g10read`；绝不暴露原始表/列/值 CRUD（op 1 增 / 2 改 / 3 删）。
3. **聊天转发**：绝不转发客户端自选 SubType/PushLog id——入站玩家聊天强制纯文本子类型，PushLog 只服务端产生；服务端组 PushLog 时校验 JSON 参数长度/类型与模板占位符完全匹配（封 SubType==87 崩全服）。
4. **领奖类命令（351 及 350/3690/325/326/880）**：按权威累计充值（服务端支付记录）独立算完成度、档位资格、领取次数、时间窗；拒绝超出已赚状态的客户端档位/Status/活动 id。
5. **会话认证与防重放**：把 checkCode/num3 当非认证、CmdIndex/SID 当不可信。会话绑服务端签发的高熵短期 token；按已认证身份授权包内 userId/serverId/sid；按会话单调序号窗 + 时间窗拒绝重复/越窗帧。
6. **服务端自身上行解析器加固**：任何 `new byte[declaredLen]` 或分帧分配前校验 `0<len<=MAX` 且 `0<declaredDecompressLen<=MAX`，逐包包裹异常，一个畸形客户端帧不能 OOM 或弄挂服务端（客户端 H1 的对称教训）。
7. **WebView/URL egress**：对每个服务器/邮件/配置来源 URL 在到达任何客户端 WebView 前强制官方域白名单（host + https）——邮件 Url、verify_page_url、公告链接、announce 配置、GM 'JL' 路径。绝不把 FULL_UIN/角色 id/GM token/问卷 token 放进未 pin host 的查询串；绝不下发 JS 体/URL 作为 customJS。
8. **广播 egress 内容审核与长度限制**：服务端审核所有玩家可写文本（聊天、昵称、军团名、横幅、邮件），独立于客户端 region 标志（IsOverseas）；转发前强制最大字节/字符长度 + 最大标记 token 数（封接收端富文本 CPU/内存 DoS 和国内不过滤缺口）。
9. **不信任客户端完整性/版本/特权自证**：绝不按客户端上报的构建哈希、DevMode、IsInnerPackage、GMSdkMode、版本串、程序集哈希自证授予特权；每个玩法动作服务端重校验。（客户端另行：热更包按 pin 公钥签名，解压前、加载任何 DLL 前验签。）
10. **UGC 资源引用**：用户设置的图片（家族图标、自定义照片）只存不透明 asset id，服务端解析到 pin 的官方 CDN；拒绝/规范化任何完整 URL，使客户端绝不去取攻击者选的 host。
