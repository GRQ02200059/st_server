# 客户端权威计算专项 — 第三轮(核心货币/花费链路)

> 生成日期 2026-07-27。续[第一轮](客户端漏洞审计-2026-07-27-客户端权威计算.md)、[第二轮](客户端漏洞审计-2026-07-27-客户端权威计算-第二轮.md)。本轮专查核心货币/花费主链路,重点是你提的"**扣费在客户端做**"。判别器不变:客户端算完的成本/金额/资格**是发上去(危险)还是只显示、服务端从自己价格表扣(安全)**。所有 file:line 手工二次核对。只列新增,不重复前两轮 16 条。

## 0. 一句话结论

**有,4 条新的核心货币风险**,而且第 1 条正是最典型的"扣费在客户端做":**迁城的免费/付费,由客户端一个二元标志 mIsFree 决定,成本金额本身根本不上包——服务端只要信这个字节,就是无限免费迁城。**

另 3 条把**货币金额直接放上线**:绑元宝/非绑分账(cmd 4271)、军团红包玉符金额(cmd 3300)、即时征兵的兵源池选择(cmd 38)。

好消息(诚实说明):**大部分花费链路是安全的**——所有加速道具(831/802/837)、招贤(710)、十周年红包(3306)、抽卡保底/心愿(301/304/309)都确认**只发意图/id,服务端从自己的表扣费/发货**。危险的只有这 4 条真把金额/资格放上线的。

## 1. 🏙️ cmd 851 迁城:免费/付费标志客户端算,成本不上包 【HIGH · 最典型的"扣费在客户端做"】

- **计算**:`RoleForcesMoveCityUINew.cs:1384` `mIsFree = 1;`,`:1406` 在 `if (!flag)` 里 `mIsFree = 0;`——flag 只由客户端本地读取(赛季标志、军团 NPC 城归属、建设城免费时间、是否首次迁城)翻转。
- **发送**:`:1483` `Send<List<object>>(851, obj)`,包体 = `{targetWid, mIsFree, autoGiveupInvalidSupplyBuild}`。**成本金额 `MOVE_MAIN_CITY_YUBAO_COST` 从不上包**(只用于本地显示/预检)——所以线上唯一的免费 vs 付费开关,就是这个被信任的客户端字节。
- **利用**:构造 cmd 851,对任意目标 wid 发 `mIsFree=0` → 服务端不扣元宝/虎符直接迁城 → **无限免费迁城**,白嫖高价值货币坑 + 战略重定位。
- **服务端必须**:**无视客户端 mIsFree**,按权威状态自己重算免费资格(赛季 S1Tslh/ExFhwj、目标地图区城的军团 NPC 城归属、IsOpenCityConstruction、服务端时钟的建设城免费时间、IsFirstMoveCityDone);算出付费就扣 `MOVE_MAIN_CITY_YUBAO_COST`、余额不足拒绝;目标 wid 合法性/冷却也要重校验。

## 2. 💰 cmd 4271 绑/非绑元宝分账:客户端决定从哪个池扣多少 【HIGH】

- **计算**:`BuyHufuUI.cs:964` `num = (BindYuanbaoServerFAI >= curValue) ? curValue : BindYuanbaoServerFAI;`——即跨服转移用多少**绑定(促销)元宝** vs 真实元宝。
- **发送**:`:968-971` `Send<List<object>>(4271, { resType, curValue, num })`——`num` 是**告诉服务端从哪个货币池扣、扣多少的指令**,不是显示串。`curValue` 是用户文本输入,只在客户端夹到 99999。
- **利用**:改包客户端不管真实绑定余额,发 `num=curValue`(或任意大整数),声称整笔转移都用不存在的免费/促销绑定元宝出 → **真实元宝零消耗**。
- **服务端必须**:无视客户端 num,按调用方权威绑定元宝余额重算分账 `bound_spend = min(server_bound_balance, cost)`、`unbound_spend = cost - bound_spend`;curValue 按真实资源/汇率/每笔上限重校验;拒负数/溢出;**绝不让客户端选扣款池或金额**。

## 3. 🧧 cmd 3300 军团/家族红包:玉符金额+份数客户端选,所有门禁本地 【HIGH】

- **计算**:`UnionRedPacketSend.cs:320` `int num = ConvertLabelNum(...["lb_num"])`(从 UI 标签读金额),`:321` 仅客户端可负担性检查 `if (num > YufuOwned)`(YufuOwned = UserData.UnbindYuanbao)。100~2888 金额范围、10~100 份数、20000/日上限、6 秒冷却、禁发检查**全在客户端**。
- **发送**:`RedPacketData.cs:922` `RequestSendRedPacket(totalCount, totalNum, ...)`,`:937-942` `Send<List<object>>(3300, {..., totalCount, totalNum})`——`totalCount` 就是**货币面值和要扣的总额**,不是重定价的模板 id。
- **利用**:改包发 totalCount 超过真实 UnbindYuanbao、超出 100~2888、超 20000/日、或禁发/冷却期。若服务端按客户端 totalCount 出红包而不独立扣款 → **伪造超过持有量的红包(跨账号货币注入)**;即便不超额,范围/上限/冷却/禁发绕过也能刷屏或乱发。
- **服务端必须**:要求发送方权威 UnbindYuanbao ≥ totalCount 并**原子扣正好 totalCount**;enforce `100≤totalCount≤2888`、`10≤totalNum≤100`、`totalNum≤totalCount`;服务端时钟跟踪 20000 玉符/日上限 + 6 秒冷却;军团/家族禁发+成员校验;每份金额由服务端自己拆分,**绝不用客户端每份值**;channelID/descStr 服务端校验。

## 4. ⚔️ cmd 38 即时征兵:兵源池类型选择客户端算 【MEDIUM】

- **计算**:`ArmyConscriptingImmediatelyView.cs:2129` `int num3 = (mIsUsingShipCarryRedif ? 3 : mIsUsingPolicyRedif ? 4 : ... : 1)`——兵源类型(1=自有/3=船载/4=政策/5=木营/要塞/7=NPC载),纯从客户端 UI 布尔选。
- **发送**:`ConscriptOpRequest.cs:123-124` `Send<List<object>>(38, { conscriptingInfo, conscriptType })`。
- **利用**:伪造 conscriptType 指向军队并不拥有的政策(4)/船载(3)/NPC载(7)/要塞(5)池,或规避自有池(类型1)本来要付的**体力消耗**(同一批客户端标志还决定是否扣体力)。
- **服务端必须**:服务端自己重推该军队合法拥有哪些兵源(战舰赛季+ship_id、政策可用性、驻城预备、木营、NPC城),只从拥有的池消耗;体力/资源按权威上下文扣,无视客户端标志。

## 5. ✅ 确认安全的(服务端从自己表扣费/发货)

| 项 | 为何安全 | 证据 |
|---|---|---|
| **加速练兵** cmd 831(及 800/65/6/193/79/69/663) | 只发 `[wid, armyId, count, needPortWid, useSpeedup=0/1]`;count 服务端重定价,useSpeedup 纯意图,无道具/成本上包 | ArmyOp |
| **加速农田/练兵** cmd 802/837 | 只发 `int[]{armyId}`,无道具/成本/减免时间;服务端重算剩余时间、从自己库存扣道具 | `ArmyOpRequest.cs:1852` |
| **招贤** chat cmd 710 | 成本 `CHAT_ZHAO_XIAN_COST_YUANBAO` 只用于决定兑换弹窗;包里只带招募子类型+可选 teamId,无金额 | `UnionZhaoxian*` |
| **十周年/活动红包** cmd 3306 | 包体 `{channelID, goodsId, wishTips}`;可负担性是客户端置灰;无金额/数量/货币上包 | — |
| **抽卡保底/心愿** cmd 301/304/**309** | 保底 CurScore/IsGuaranteed 从服务端复制的 `Tb_user_wish_hero.score` 读,只做显示/动画;替换成本服务端算 | `WishHeroData.cs:246` |

**要点**:显示成本 ≠ 危险。这 5 类客户端都能算/显示成本,但发上去的只有意图/id,服务端从自己的表扣——这才是正确姿态。危险的是第 1~4 条那种把金额/资格放上线。

## 6. 服务端重算清单(第三轮新增,接前两轮)

20. **cmd 851**(迁城):无视 mIsFree,服务端重算免费资格,付费就扣 `MOVE_MAIN_CITY_YUBAO_COST`。【最典型扣费漏洞】
21. **cmd 4271**(绑/非绑元宝转移):无视 num,按权威绑定余额重算分账;curValue 按真实资源/上限重校验。
22. **cmd 3300**(军团红包):要求 UnbindYuanbao≥totalCount 原子扣款;enforce 金额/份数范围、日上限、冷却、禁发、成员;每份服务端拆分。
23. **cmd 38**(即时征兵):服务端重推合法兵源池,只从拥有的池消耗,体力/资源按权威扣。
24. **cmd 3306**(十周年红包,残留):校验 goodsId 是真红包货物、账号持有≥1、原子扣一个再发;校验发送方有权发到该目标。
25. 招贤 710 / 加速 802,837,831(残留):成本/道具从服务端配置/库存扣,enforce 每日招募数/冷却/加速道具拥有。
