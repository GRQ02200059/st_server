# 正版战报战前动作差距审计（2026-07-30）

## 范围与方法

本审计只比较首个 `09x` 回合动作之前的战报动作。

一手来源：

- `assent/cfg/paper` 下共找到 28 份含 `report` 字段的正式 JSON；
- 其中 25 份包含首个 `09x`，可完整截取战前段；
- 主例：`assent/cfg/paper/11/cap_20260312014510506_0000000b_zlib.json`；
- 当前实现：`ClientBattleTextReplayProtocol.kt`、`ClientBattleTextReplayAdapter.kt`。

统计口径：

- 动作前两字符按 base36 解码为十进制动作 ID；
- 参数宽度是动作码之后以逗号分隔的字段数；
- 25 份完整样本在首个 `09x` 前共观察到 111 种动作码；
- 语义只在能由稳定形状、前后文或具体配置 ID 交叉验证时确认；其余标为“推测”或“无法确认”。

## 结论摘要

当前实现已经补上 `5p` 的结构、四类战法发动码、四维变化、`ja` 和部分状态，但与正版仍有三个 P0 级差距：

1. **阶段顺序不兼容。** 正版将通用/阵营/兵种/装备及被动效果放在 `04` 前，将指挥效果放在 `04` 后；当前适配器先写 `04`，再遍历全部事件，因此被动及其他 round 0 效果也全部落到 `04` 后。
2. **“初始属性”编码并非正版格式。** 当前用 `19/1a/1b/1c` 输出 `来源=0、变化量=0` 的合成属性行；25 份正式样本中没有一条这样的记录。正版的属性展示始终绑定真实系统、阵营、兵种、装备或战法来源。
3. **静态加成来源丢失。** 当前模型只保留算完后的入场属性，没有保留 `0k/5s/7x/ba` 等来源流水，因此即使最终数值正确，也无法生成正版客户端显示的“哪项效果带来多少变化”。
4. **属性精度和字段语义仍不一致。** 当前 `BattleStats`、成长值、变化量和应用后值都使用整数；正版属性流水普遍保留一位小数。百分比属性效果还需要区分“配置强度”和“对具体目标实际造成的属性变化量”。

### 2026-07-31 `ja` 精确对齐里程碑

定向回归由 `OfficialPreparationReportDiffTest`、`OfficialReportFixtureTest`、

## 正版稳定阶段顺序

25 份完整样本的共同骨架是：

```text
基础展示/5p
  → 通用规则 0k
  → 阵营/组合 5s
  → 兵种及系统附加 7x
  → 装备 ba
  → 其他系统段 96
  → 被动战法 0l
  → 60
  → 04
  → i3
  → 按武将的 05 / hw / 指挥 0m / hx
  → 08
  → 首回合 09x
```

主例中的具体位置：

- `0l1,200689` 等被动从动作序号 447 开始；
- `60#04` 位于序号 480–481；
- `i3` 位于 482；
- `053#hw3#0m3,200023...#hx3` 是一名武将的指挥段；
- `08#091` 位于 624–625。

当前 `ClientBattleTextReplayAdapter.adapt()` 在武将信息和合成属性行之后立即追加 `PREPARE(04)`，随后才遍历 `result.events`。因此即便事件中的 `BATTLE_PASSIVE` 被正确编码成 `0l`，它也仍处于错误阶段。

### 已覆盖但格式或语义不完整

#### 1. `5p`（205）

正版固定 19 参数：

```text
5p1,45,9700,200028,10,200689,10,200233,10,3106,3104,,400114,6,400115,6,400112,1,0
```

当前结构相同，但真实数据来源仍不完整：

- 正式样本中的战法等级存在 1、7、8、9、10，并非统一值；
- 兵种特性是实际的 `31xx/32xx/33xx`；
- 装备 ID、等级存在 1、4、6、8、11、12 等实际取值；
- 当前玩家状态若没有持久化这些养成数据，只能输出默认值或空槽。

因此 `5p` 的字段数量已经对齐，字段内容尚未完全对齐。

#### 2. `19/1a/1b/1c` 与 `1g/1h/1i/1j`

正版 6 参数形状稳定：

```text
190,295020,2,10,15.6,191.3
1g3,200023,4,22,28.9,135.5
```

可确认参数是：

```text
来源位置,来源效果/战法ID,目标位置,等级/持续类值,变化量,应用后值
```

当前真实 `StatChanged` 投影与此形状接近。但 `initialAttributes()` 另行生成：

```text
190,0,1,0,0,100
```

审计的正式属性动作中，来源 ID 从未为 0。常见真实来源包括：

- `295020`、`295040`：系统/通用加成；
- `291002`、`291004`、`291005`：阵营或组合类加成；
- `200023`：指挥战法；
- `400027` 等：装备效果。

所以当前合成“初始属性行”不是正版存在的协议形态，应由带 provenance（来源）的真实静态加成流水替代。

此外，当前数值本身还没有对齐正版：

- `hero_table.csv` 中基础属性和成长值以百分位整数保存，例如 `attack_grow=142` 表示约 `1.42`；当前 `scaledStat()` 通过 `(value / 100.0).toInt()` 直接截断成 `1`。
- `BattleStats`、`BattleEvent.StatChanged.delta/valueAfter` 都是 `Int`，无法表达正版的 `28.9`、`135.5`。
- 对百分比属性效果，当前事件把 `potency.value`（例如 `22`）作为 `delta`；正版第四参数可出现配置强度 `22`，第五参数则是根据目标属性计算出的实际变化量 `28.9`，两者不是同一个字段。

因此当前虽然已经输出 6 参数，但“配置强度、实际变化量、应用后值”尚未建立各自独立且保留小数的数据字段。

#### 3. `0s/0t`（28/29）

正版均为 2 参数：

```text
0s目标位置,效果ID
0t目标位置,效果ID
```

当前也输出 2 参数。28 份可读战报统计显示，`0s` 和 `0t` 的效果 ID 大量重叠，
因此把二者定义为“正面/负面”并不可靠：

- 正版 `0s` 同时出现 `752` 等控制效果和 `531/533` 等增益修饰；
- `0t` 会与 `0s` 在同一指挥战法下交错出现，如 `0s4,752#0t5,952`；
- 部分样本中 `0t` 与 `ja` 同段，可能表达未命中、冲突、抵抗或失效，而不是单纯的“负面状态”。

结论：成功的 `StatusApplied` 已按生命周期语义固定投影为 `0s`，并优先使用配置效果 ID。
`0t` 更可能属于冲突、抵抗或未生效分支，但精确状态机尚不能确认，当前不主动生成。

#### 4. `8c`（300）

正版稳定为 2 参数，例如：

```text
8c5,213900
8c1,451038
```

它用于已验证的派生战法链，也可在装备初始化上下文出现。当前通用投影只接受
`210xxx–213xxx` 与 `45xxxx` 的已验证范围；未知派生 ID 会记录诊断并省略。
装备特性的稳定初始化动作另为 `8x`，不再用 `8c` 猜测替代。

#### 5. `ja`（694）

正版稳定为 5 参数，当前使用 `amount` 作为末字段与主例吻合。但当前只能投影引擎已经产生的 `ModifierApplied`：

- 系统规则、兵种、阵营、装备已直接汇总入属性时，缺少相应事件；
- 覆盖、刷新、冲突和未生效场景不能只靠一个 `ModifierApplied` 表达；
- 因而格式基本对齐，来源完整度不足。

`200220`（反计之策）的主动战法伤害降低并不使用通用 `ja`。主样本战前段为：

另外，全量 paper 中 `5u目标,207` 共检出 28 条，但在首个 `09` 回合动作之前

#### `20002316 / effect 171` 的主动战法射程

主样本正式指挥段还有三条：

```text
103,200023,1,1,5
103,200023,2,1,4
103,200023,3,1,3
```

配置证据为 `detail=20002316`、`effect=171`、`select_skill_param=3`、
`constant_param=1`，语义是我军全体“主动战法有效距离 +1”。最后一列分别是三名
武将基础攻击距离 `4/3/2` 加一后的展示值 `5/4/3`。

现已把该 detail 接入独立的战法射程状态：只对 `SkillKind.ACTIVE` 的目标选择范围
增加 1，不修改普通攻击距离；同时生成三条与正式样本精确一致的 `10` 动作。
其他 `effect=171` 还包含指定子战法、所有战法、主战法等不同语义，仍不做通用猜测。

## 无法确认、暂不应猜测的内容

以下内容仅凭 `paper` 动作串不能安全定名：

- `0s/0t` 的精确状态机含义；
- `61/66/67` 三层包络分别对应哪种客户端对象生命周期；
- `96 + 281xxx/285xxx` 的准确业务分类；
- 装备专用动作族中每个 ID 的效果名称和参数顺序；
- `44/45` 两个双方汇总值的含义；
