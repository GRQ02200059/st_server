# 客户端魔改联调手册（本地私服联调用途）

> 用途界定：仅用于让本地客户端连接**自己的 Kotlin 私服**、开启调试、跳过无关流程，做协议联调。
> 不涉及网易线上服务器、不针对真实玩家。属正当逆向研究。

---

## 0. 完整性校验研判结论（决定路线可行性）

双代理 + 手动静态审计，三层全部确认**无硬校验拦截**：

| 层 | 结论 | 关键证据 |
|---|---|---|
| Managed(C#) | 不校验 DLL hash | `_assembly_hashes.json` 仅经 `AddAssemblyHash` 转发 native + 热更重启决策；`WithVerify` 枚举 managed 零引用 |
| Native(libclient.so) | NXPK 加载无完整性校验 | `NpkReader::Load/ReadNewFileNames` 只比对 magic `0x4E58504B`，直接 Decrypt+解压，无 hash 分支 |
| 唯一相关机制 | 软告警不阻断 | `LoadRuntimeConfigAndComputeAssembliesHash` 把各 DLL hash 聚合成 uint64 打 log，错误分支全走 `LogWarning`，无 abort |
| 其余 so | 都不管游戏文件 | libsec-lib=反Xposed / libturingmfa=反外挂 / libEncryptor=通用加密 / Mono=只查 PE 格式 |

**唯一残留风险**：聚合 uint64 hash *可能*被上报服务端——但服务端是你自己的私服，不校验它即可无视。

**结论**：三条路线全部畅通，纯按"改动最小/迭代最快"选。

## 1. 四个联调目标

| # | 目标 | 靶点 | 说明 |
|---|---|---|---|
| 1 | 重定向服务器到私服 | `GameConfig.LoginIp` / `LoginPort` | 模拟器→宿主机用 `10.0.2.2` |
| 2 | 开 DevMode | `GameConfig.DevMode` | 解锁 GM 命令、内网调试路径 |
| 3 | 跳更新/热更 | `GameConfig.UpdateAddressLocal` 或 DevMode 分支 | 避免拉官方 patchlist |
| 4 | 跳实名 | 私服 99992 已返回 `[1,null,ServerSession,userId]` | **无需改客户端**，服务端已处理 |

## 2. 三条路线对比

| 路线 | 改什么 | 受 native 校验影响 | 迭代速度 | 推荐度 |
|---|---|---|---|---|
| ① UserDefault 旁路 | 3 个本地键，不碰字节 | 完全免疫 | 最快 | ★★★★★ 首选 |
| ② 改 DLL 重打包 npk | `GameConfig.cs` 方法体 | native 已放行 | 慢（每次重打包） | ★★★ 需持久化改逻辑时用 |
| ③ Frida 运行时 hook | 内存改返回值 | 绕过静态校验 | 中 | ★★★ 无 root/不想动包时用 |

## 3. 路线①：UserDefault 旁路（首选）

原理：`GameConfig` 三个 getter 都是"UserDefault 有值就优先用"：

- `LoginIp`  → 读 `_Key_Login_IP_`（非空即用）— GameConfig.cs:302-317
- `LoginPort` → 读 `_Key_Login_Port_`（非0即用）— GameConfig.cs:331-346
- `DevMode`  → 读 `_Key_Dev_Mode_`（=="True"）— GameConfig.cs:285-300

实际连接点：`NetConnection.cs:194 mConnectIp = GameConfig.LoginIp`

### 方式 A：内置 GM 面板（最正门，零文件改动）

客户端自带 `GmConfigView`，输入框直接映射到 `GameConfig.LoginIp/LoginPort/UpdateAddressLocal`，点确认 → `Restart()` 生效。
调出路径：DevMode 暗号序列进 GM（见《联调操作手册.md》中记录的暗号 + 密码）。
优点：走游戏原生 `setStringForKey`+`saveFileDynamic`，落盘格式绝对正确，重启即生效。

### 方式 B：adb 直接写 UserDefault 落盘文件

UserDefault = cocos2d-x `UserDefault`（Engine.Native.Patch/cc/UserDefault.cs），落盘为 writable 目录下的 `UserDefault.xml`（网易版可能加密）。

```bash
# 1. 先运行一次游戏，让文件生成，再定位它
adb shell run-as <包名> find /data/data/<包名> -name "UserDefault*.xml"
# 2. 若明文 xml：pull → 加三个 <key>/<value> 节点 → push 回去
# 3. 若加密：放弃直写，改用方式 A（GM 面板）或路线③
```

> 注意：网易 NeoX 的 UserDefault 常有异或/加密，方式 B 不一定可行。**优先方式 A**。

要写入的键：
```
_Key_Login_IP_   = 10.0.2.2
_Key_Login_Port_ = <你的私服端口>
_Key_Dev_Mode_   = True
```

## 4. 路线②：改 DLL 重打包 npk（需要改逻辑时）

适用：不只改地址，还要改方法体逻辑（如强制跳过某校验、注入调试日志）。

### 步骤

1. **改 IL**：用 dnSpy/ILSpy 打开 `assembly_extracted/Game.Core.dll`，改 `GameConfig` 相关 getter（如让 `DevMode` 直接 `return true`、`LoginIp` 直接 `return "10.0.2.2"`），重编译保存。
2. **重打包 NXPK**（复用 `tools/stzb_cfg_extract.py:39-51` 的格式知识）：
   - 保持 magic `NXPK`(4B)
   - 每条目 28B 结构不变：name hash / offsets / compressed len / original len / zflag / EncryptType
   - 单文件 `EncryptType` 保持原值（否则 Decrypt 出乱数据），或写未加密(0)+ 修正 zflag
   - `zflag` 压缩方式与实际内容匹配
3. **同步刷新 hash**（消除上报风险）：改完后重算该 DLL 的 MD5→base64→写回 `assembly_extracted/_assembly_hashes.json` 对应条目。或干脆私服不校验聚合 hash。
4. 重打进 APK → 签名 → 装机。

> 成本：每次改都要重打包+重装，迭代慢。仅在改地址不够、要改逻辑时用。

---

## 5. 路线③：Frida 运行时 hook（无 root 备选/绕静态校验）

适用：不想动包、或担心任何静态校验。因为是 Mono，可直接 hook C# 方法（frida-mono / 直接 hook native delegate）。

思路：hook `GameConfig` 的 `get_LoginIp`/`get_LoginPort`/`get_DevMode`，返回定值。
或更底层：hook `NetConnection` 里读 `mConnectIp` 的赋值点。

> 因 Mono metadata 明文，符号可解析；比 il2cpp 好 hook 太多。

---

## 6. 推荐组合

- **日常联调（改地址/开调试）**：路线① 方式 A（GM 面板）。零文件改动，重启即生效，最干净。
- **要改客户端逻辑**：路线②，改完记得刷 `_assembly_hashes.json` 或私服忽略聚合 hash。
- **不想动包 / 快速试探**：路线③ Frida。
- **实名**：无需任何客户端改动，私服 99992 已返回跳过。
