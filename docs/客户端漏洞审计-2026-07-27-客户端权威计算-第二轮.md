## 0. 一句话结论

**有,而且找到了你最担心的那种——客户端自己掷随机数、再把结果发上去。** 冬至钓鱼(cmd 4911)客户端 `new Random()` 掷出鱼种和重量,直接把 `{场景id, 鱼种, 重量}` 发给服务端当"钓到的结果"结算。

本轮新增 **11 条**"客户端算+发送"的服务端信任风险,集中在三块:**小游戏自评结果、武将加点/洗点、战令/活动进度自报**。

好消息:大部分随机数是安全的——**占卜、狼人杀、烟花、纪念册的 `Random` 都只喂本地显示、从不上包**;玩家交易卖出(6419/6421)、开箱(6060)也只发意图,金额由服务端下发。

**最值得优先修的不是钓鱼,是 cmd 80 武将加点**——它给的是**永久战斗属性**,直接破坏 PvP 平衡,比小游戏奖励影响大得多。

## 1. 🎲 客户端掷随机数发结果(皇冠级——你问的那种)

### #1 cmd 4911 冬至钓鱼:客户端掷鱼种+重量并发送 【HIGH】

- **计算**:`FishingLogic.cs:206` `int num10 = new Random().Next(1, num2 + num + 1);`(掷鱼种);`:240` `mWeight = WinterSolsticeUtils.GetFishWeight(...)` → `WinterSolsticeUtils.cs:562` `int num2 = MathUtil.RandomInt(1, num);`(掷重量)。还有 `mTestMode` 分支能任意设重量。
- **发送**:`WinterFishingMainPanel.cs:936` `Send<object[]>(4911, new object[3] { mSceneId, fish, weight }, OnRespondGameEnd)` —— 包里直接带 roll 出来的鱼种和重量,**不是让服务端重 roll 的种子**。
- **利用**:跳过小游戏,直接发 `{场景id, 最稀有鱼种, 最大合法重量}`,每次都收获顶级钓鱼奖励。
- **服务端必须**:按 `Tcfg_winter_solstice_fish` / `Tcfg_fish_weight_probability`(按 sceneId)**服务端自己掷**鱼种+重量,扣鱼饵/次数,只按服务端结果发奖;包里应只带 sceneId + 一个次数令牌。

## 3. ⚔️ 武将加点/洗点(核心玩法,最高价值——影响 PvP)

### #3 cmd 80 加点:客户端选的每属性点数直接发送 【HIGH · 优先修】

- **计算**:`HeroCardAddPointNewComponent.cs:1819` 每次 +1,**仅由本地 `mLeftPoints` UI 守卫约束**(种子来自 `heroInfo.point_left`)。
- **发送**:`CardOpRequest.cs:951` `Send<object[]>(80, new object[5]{ heroUid, attackPoint, defencePoint, intelPoint, speedPoint })`。同类:沙盘 cmd 3443(`:960`)、3453(`:969`)。
- **利用**:对某 heroUid 发 `attackPoint=99999`,若服务端原样存 → **无限免费永久属性**,远超 point_left。`mLeftPoints<=0` 门禁纯本地。
- **服务端必须**:按权威 `point_left` 重算预算;拒绝 `sum(四项) > 剩余点` 或任一项 <0 或超每属性上限;结果属性服务端推导;绝不原样存客户端分配。

### #7 cmd 185 保存加点方案:客户端每属性值持久化,无可见预算校验 【MED】

- `CardOpRequest.cs:995` 取 `planTmpAddedPropValues[1..4]`,`:1008` `Send<List<object>>(185, ...)`。之后 cmd 186 切换时只发 id、应用已存的数。
- **服务端必须**:**保存时**校验(各≥0、和≤point_left、≤每属性上限);cmd 186 应用时**再校验一次**存储方案总量对当前 point_left——别假设保存时的校验仍成立。

### #11 cmd 186 洗点免费标志:客户端按可伪造 ServerTime 自己算 【MED】

- **计算**:`HeroCardWashPointConfirmView.cs:121` `return mCleanPointTime + 604800 <= GameTime.ServerTime;`(ServerTime 可伪造),元宝扣费也客户端做。
- **发送**:`CardOpRequest.cs:980` `Send<int[]>(186, new int[3]{ cardID, planID, isFree })` slot3=isFree。
- **利用**:永远发 `isFree=0`(或把 ServerTime 调大让 IsCostFree 返回 true)→ 跳过 `HERO_CLEAN_POINTS_YUANBAO` 扣费和 7 天冷却。
- **服务端必须**:无视 isFree;按服务端存的 `clean_point_time + 604800` vs 权威时间重算免费资格,自己扣元宝、自己 enforce 冷却。

## 4. 📋 战令/活动进度自报

### #4 cmd 6236 / 5228 战令任务条件完成:客户端自报 {条件id, 次数} 【HIGH】

- **发送**:`Activity10thBpData.cs:163` `Send<int[]>(6236, new int[2]{ conditionId, count })`;春节 `NewYearBpData.cs:888` cmd 5228;通用 `BpActivityData.cs:593`。触发点全是**纯 UI 事件**(打开外观面板、进入场景、SDK 分享),服务端无法独立观察。
- **利用**:重放 cmd 6236/5228,任意 conditionId + 灌大 count,一次性完成所有战令任务,领全部档位(含付费轨)。
- **服务端必须**:只按服务端观察到的底层动作记条件;无视客户端 count(每个已验证事件最多 +1);拒绝服务端没观察到的 conditionId;把"UI-only 条件"(开面板、进场景)改成服务端权威信号或移出奖励门禁。

### #9 cmd 6418 春节2026集市:生产技能点分配整数组发送 【MED】

- `ActivityNewyearFestival2026TradeTechniqueUI.cs:284` 本地改 `produceSkillLevels[type]`,`:287` `Send<int[]>(6418, array2)` 发整个 int[5]。预算 `GetMarketTechPointLeft()` 客户端算。
- **利用**:发 `[3,3,3,3,3]` 使和超过 skill_level → 免费额外生产档,拉高产出/贸易收益。
- **服务端必须**:拒绝/夹取 `sum(levels) > skill_level`、任一 level 超每类型上限、或非连续跃迁;分配服务端重算。

## 5. ✅ 确认安全的(客户端算但只显示 / 服务端权威)

| 项 | 为何安全 | 证据 |
|---|---|---|
| **占卜** 随机点位 | `new Random` 建地图点坐标,只序列化到本地 UserDefault,无 Send | `DivinationData.cs:362` |
| **狼人杀** 随机 | `RandomVoteEffectPos()` 只返回屏幕特效坐标,无 Send | `ActivityWerewolfGameData.cs:1387` |
| **烟花** 随机摆位 | Fisher-Yates 自动选空位,但该方法**零调用者**(死代码) | `ActivityFirework2025Data.cs:197` |
| **纪念册** 随机年度武将 | `new Random().Next` 选本地"年度武将"喂显示;唯一 Send(cmd 986)只带 `{mode, roleId, year}` 意图 | `MemoryBookData.cs:1010` |
| **玩家交易卖出** 6419/6421 | 只发 `[tradeType, target, count1..5]`;预览售价/收益是**从服务端下行解析来的**显示串 | trade-sell 路径 |
| **开箱** cmd 6060 | 包里只带 `[user_item_id, [useNum]]`,真实发放量由服务端下行 | `ResourcePackageItem.cs` |

**要点**:随机数本身不危险,危险的是"随机数结果被发送"。本轮唯一踩线的就是钓鱼(#1)。

## 6. 服务端重算清单(第二轮新增,接第一轮 §4)

11. **cmd 4911**(冬至钓鱼):服务端自己掷鱼种+重量,拒绝客户端 fish/weight。【皇冠】
12. **cmd 27050**(大亨钓鱼结算):无视 success 标志和 hit/crit/miss,按 27061 下发的鱼血 + 时间戳事件/种子重建。
13. **cmd 80 / 3443 / 3453**(加点):拒绝 `sum(四项) > point_left` 或越界;属性服务端推导。【优先】
14. **cmd 185**(存加点方案):保存时校验,cmd 186 应用时再校验。
15. **cmd 186**(洗点):无视 isFree,服务端按 clean_point_time+604800 重算并扣元宝/enforce 7 天 CD。
16. **cmd 6236 / 5228 / FinishCondition**(战令条件):只按服务端观察记条件,无视 count,拒未观察的 conditionId。
17. **cmd 5175 / 5178 / 4054**(打蛋/抓蟹/舞龙):按回放/权威棋盘重算分数,拒不可复现的成绩;时间按服务端时钟。
18. **cmd 6418**(集市技能点):夹取 `sum > skill_level` 或越界的 levels 数组。
19. **cmd 5061**(龙舟结局):要求上传选择序列,服务端重算 resultId。
