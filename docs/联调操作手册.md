# 率土之滨 私服 —— 模拟器联调操作手册 (P1 → P3)

本手册指导你把反编译的《率土之滨》客户端 (`com.netease.stzb`) 重定向到本地 Kotlin 私服，
走通 **握手 → 平台校验 → 服务器列表 → 登录进城** 全流程，并进入 P3 逐包联调阶段。

> 依据均来自反编译源码，关键行号在文末「代码依据」列出。

---

## 0. 前置：启动私服

```bash
cd /Users/bytedance/stzb/server
STZB_PORT=59979 ./gradlew run
```

- 服务端默认绑定 `0.0.0.0:59979`（所有网卡），模拟器可访问。
- 看到 `=== stzb-server (P0) 监听 :59979 ===` 即就绪。
- **联调时盯这个终端的日志**：
  - `<< cmd=X ...` = 已识别并回包的上行
  - `⚠ 未处理 cmd=X ... body: {...}` = 尚未实现的业务包 —— **把这些发我，逐个补**

---

## 1. 让模拟器能连到私服

模拟器访问宿主机（跑私服的 Mac）有两种地址，二选一：

| 模拟器类型 | 访问宿主机的地址 |
|---|---|
| Android Studio AVD（标准）| `10.0.2.2` |
| 夜神 / MuMu / 逍遥等 | 宿主机局域网 IP（`ipconfig getifaddr en0` 查），如 `192.168.x.x` |

> 下文以 `<HOST>` 代指上面选定的地址，端口用 `59979`。

⚠️ **架构注意**：本 APK 是 arm il2cpp。x86 模拟器需开启 arm 翻译（夜神/MuMu 的兼容模式，或用 arm 镜像的 AVD），否则客户端起不来——这与私服无关，是运行环境问题。

---

## 2. 开启 DevMode（客户端调试模式）

DevMode 是解锁 GM 面板和内网直连的总开关。三选一，推荐**方式 A**：

### 方式 A：登录界面暗号（推荐，无需 root）
1. 启动客户端，停在登录界面。
2. 在登录界面按顺序点隐藏触摸区：**左 · 右 · 右 · 左 · 左 · 左 · 右 · 右**（共 8 下）。
3. 弹出密码框，输入：`g10#debug`
4. 进入 GM 面板 → 勾选 **DevMode** 复选框 → 按提示重启客户端。
5. 重启后登录界面会**自动出现 GM 浮动按钮**（DevMode 已生效，之后不必再点暗号）。

### 方式 B：预置文件（需 root / adb 可写）
往 `/data/data/com.netease.stzb/files/UserDefault.xml` 写入（建议先让游戏跑一次生成该文件再照改）：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<userDefaultRoot>
    <_Key_Dev_Mode_>True</_Key_Dev_Mode_>
    <_Key_Login_IP_><HOST></_Key_Login_IP_>
    <_Key_Login_Port_>59979</_Key_Login_Port_>
    <use_intra_server_server_host>true</use_intra_server_server_host>
</userDefaultRoot>
```
- `_Key_Dev_Mode_` 必须是字符串字面量 `True`
- `_Key_Login_Port_` 是整数
- `use_intra_server_server_host` 是 bool（`true`/`false`）

预置完这几个键后可跳过第 3、4 步。

---

## 3. 指定登录服地址（GM 面板）

DevMode 开启后：
1. 登录界面点 GM 浮动按钮（或按方式 A 暗号）进入 **GmConfigView**。
2. 填写：
   - `login_ip` = `<HOST>`
   - `login_port` = `59979`
3. 确认 → 弹「重启生效」→ 重启客户端。

> `login_ip/login_port` 指向的是**登录服**（拉服务器列表 + 99992/20003）。我们的私服单进程同时扮演登录服和游戏服。

---

## 4. 勾选内网直连（把游戏服强制指向本地）

⚠️ **关键坑**：勾内网直连后，游戏服 host 被强制成 `127.0.0.1`，但**游戏服端口取自服务器列表下发的 `port` 字段**，不是 `login_port`。

- 我们私服在 20003 响应里下发的 `port` = 私服自身监听端口（代码里动态取 `localPort`），所以天然对齐。
- 但注意 `127.0.0.1` 是**模拟器内部的 localhost**，不是宿主机！

因此有两种正确姿势：

**姿势 1（推荐，最省心）：不勾内网直连**
- 让私服在 20003 列表里把 `host` 直接下发成 `<HOST>`（宿主机地址）。
- 修改私服 [Cmd.kt](file:///Users/bytedance/stzb/server/src/main/kotlin/com/stzb/server/protocol/Cmd.kt) 里 `GameServerConfig.HOST` 为 `<HOST>` 即可，客户端直连宿主机游戏服。
- **这样连内网复选框都不用勾。**

**姿势 2：勾内网直连 + adb 端口转发**
- 勾 `use_intra_server_server_host`（内网服务器列表 UI 里的 `cb_filter` 复选框）。
- 客户端会连 `127.0.0.1:<列表port>`（模拟器内 localhost），需要把模拟器内的该端口转发到宿主机：
  ```bash
  adb reverse tcp:59979 tcp:59979
  ```
- 适合 AVD；部分第三方模拟器不支持 `adb reverse`，那就用姿势 1。

> **联调建议直接用姿势 1**：把 `GameServerConfig.HOST` 改成 `<HOST>`，跳过内网复选框和端口转发。

---

## 5. 登录进城

前面配好后，正常点「开始游戏 / 登录」：
- 客户端连登录服 → 99992 平台校验（私服签发 ServerSession）→ 20003 服务器列表 → 选服 → 连游戏服 → 99991 登录 → 加载 UserInitTable → 进主城。
- 私服终端会依次打印 `>> cmd=99992 / >> cmd=20003 / >> cmd=99991`。

**进城后开始出现 `⚠ 未处理 cmd=...` 日志** —— 这就是 P3 阶段：把这些包的 `cmd` 和 `body` 发我，我按客户端反编译逻辑逐个补响应（预计有对时、世界视野、城内建筑格子等）。

---

## 6. 反作弊说明（不阻断，无需处理）

- 易盾反作弊只是把检测结果通过命令号 **191** 旁路上报到网关，**不阻断连接**。私服收到 191 直接忽略即可（当前走 `⚠ 未处理` 分支打印，不影响流程）。
- 主协议是明文 TCP + XOR，**无 TLS / 无 SSL Pinning / 无 C# 层包签名校验**，重定向无加密学障碍。
