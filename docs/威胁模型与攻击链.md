# 《率土之滨》9.2.2 客户端威胁模型与攻击链

- **审计对象**：`stzb_9.2.2_out_branch_9.1.1776213`（il2cpp 反编译 C# 源码 + APK 解包资源）
- **审计视角**：攻击者视角。不再罗列"哪里有洞"，而是回答**"别人拿这些洞能对我们（私服运营方 + 玩家生态）做什么"**——每条攻击链给出漏洞→利用步骤→受害方→服务端拦截点。
- **审计性质**：纯离线静态分析，未运行/未修改任何文件。
- **配套文档**：本报告承接《客户端安全审计报告.md》《客户端权威性审计》，聚焦"可利用性"与"危害面"。
- **本轮新增覆盖面**：充值/内购发货、客户端间互害（聊天/邮件/UGC/WebView 注入）、自动化脚本与工作室。

## 0. 一句话结论

客户端把"服务端和其他玩家可控的内容"当可信输入，且反作弊只上报不阻断。**最致命的不是单个洞，而是它们串成的攻击链**：一个恶意账号可以远程崩全服客户端、发起放大 GET、诱导钓鱼；一个改包客户端可以白嫖商品、白拿领奖、伪造身份；一台云手机可以无门槛开工作室。**所有防线的唯一支点都在服务端**——私服必须把客户端逻辑一律视为"敌意可控"。

## 2. 攻击链详解

### 攻击链 A —— 免费发货后门（cmd 98765）｜受害方：运营收入｜烈度：致命

**漏洞**：内测发货通道 `SYS_TEST_CMD_98765` 的门槛完全由客户端控制。

```
IsInnerPackageDebugMode() = GameConfig.IsInnerPackage && GameConfig.DevMode
```

两个开关都可本地开启：`IsInnerPackage` 靠探测 `_game_config0.json` 即置真；`DevMode` 靠写 UserDefault `_Key_Dev_Mode_="True"` 即置真。

**利用步骤**：
1. 攻击者在包内放入 `_game_config0.json` + 写 UserDefault 开 DevMode → `IsInnerPackageDebugMode` 返回 true。
2. 商城购买走 `Send(98765, [11, [goodId]])` 而非真实 SDK 订单。
3. 若服务端沿用官方内测逻辑 → **不收钱直接发货**。回调 Tip 实锤"刚刚花费￥N购买了X商品"。

**依据**：
- [ConfigBeforeLoad.cs:2676-2683](file:///Users/bytedance/stzb/stzb_9.2.2_out_branch_9.1.1776213/assets/decompiled/Game.ConfigAndSdk/Tenth/ConfigBeforeLoad.cs#L2676-L2683)（后门门槛）

**服务端拦截点**：cmd 98765 在正式环境**彻底封禁**，或仅对硬白名单 GM 账号开放（且白名单在服务端，不在客户端）。

**漏洞**：一组领奖命令只发"我要领"的意图，不携带完成凭证；完成状态是客户端本地读表判定的。

### 攻击链 C —— 远程崩全服客户端（业务级"核弹"）｜受害方：全体玩家｜烈度：致命

**漏洞**：聊天/公告/邮件推送包解析时大量 unchecked cast + `string.Format`，且富文本无长度/嵌套上限。

**利用步骤**：
1. 恶意账号构造一条聊天/世界喊话，令 `PushLog` 对应的占位符与参数数量/类型不符 → 接收方 `string.Format` 抛 `FormatException`/`InvalidCastException`。
2. 或把昵称改成含未平衡 `{` 或 `{99}` 的字符串，接收方 `string.Format(..., UserName, ...)` 崩溃。
3. 或发一条 1 MiB 富文本，接收方经正则 `RichTextSplitForPlayer` + 递归表情拆分 → 每帧解析 CPU 满载 / OOM。
4. **一句喊话即可让全服看到该消息的客户端集体崩溃或卡死。**

### 攻击链 D —— 崩服 DoS（无需登录）｜受害方：全服可用性｜烈度：致命

**漏洞**：帧长 4B 大端与 zlib 解压原始长度 4B 均无上限/非负校验。

**利用步骤**：连上端口 → 发一个声明长度 `0x7FFFFFFF` 的帧，或解压后爆炸的 zlib 炸弹 → 服务端若照客户端逻辑 `new byte[声明长度]` → **单包 OOM 打崩整个进程，全服掉线**。这条最危险，**无需有效账号**。

**依据**：[DotnetBaseSocket.cs:554-559](file:///Users/bytedance/stzb/stzb_9.2.2_out_branch_9.1.1776213/assets/decompiled/Game.Network/Tenth.Network.BaseSocket/DotnetBaseSocket.cs#L554-L559)、[SocketReceiveChannel.cs:345-346](file:///Users/bytedance/stzb/stzb_9.2.2_out_branch_9.1.1776213/assets/decompiled/Game.Network/Tenth.Network.AppSocket/SocketReceiveChannel.cs#L345-L346)、[NetBuff.cs:11](file:///Users/bytedance/stzb/stzb_9.2.2_out_branch_9.1.1776213/assets/decompiled/Game.Network/Tenth.Network/NetBuff.cs#L11)

**服务端拦截点**：收包帧长 + 解压长度**硬上限 + 非负校验**，超限直接断连；限制单连接内存分配。

### 攻击链 E —— 身份伪造 / 顶号｜受害方：玩家资产、运营信誉｜烈度：高

**漏洞组合**：无 MAC 的线性校验码 + 可预测 SID + 仅判空的 Session。

- checkCode = `(cmdIndex*13)^cmdId^userId`，**任何人都能为任意 userId 算出合法校验码**（非 MAC）。
- `GenUniqueSid` = 固定前缀 `^F#$G)*Ju7(E` + 毫秒时间戳，**无随机盐**，可预测/爆破（[DotnetCmdMgr.cs:352-362](file:///Users/bytedance/stzb/stzb_9.2.2_out_branch_9.1.1776213/assets/decompiled/Game.Network/Tenth.Network/DotnetCmdMgr.cs#L352-L362)）。
- `ServerSession` 只是平台校验响应 `val[2]` 的明文串，客户端存下后原样转发，登录仅判非空（[SdkManager.cs:608](file:///Users/bytedance/stzb/stzb_9.2.2_out_branch_9.1.1776213/assets/decompiled/Game.ConfigAndSdk/Tenth.Sdk/SdkManager.cs#L608)、[LoginData.cs:3447](file:///Users/bytedance/stzb/stzb_9.2.2_out_branch_9.1.1776213/assets/decompiled/Game.Data.GamePlay/Tenth.Data/LoginData.cs#L3447)）。

**利用步骤**：构造 `userId=受害者` 的包，自算 checkCode，预测其 SID → 若服务端只用 checkCode 防篡改、只判 Session 非空 → **以受害者身份操作**（转移资源、解散联盟、送钱给小号）。事后服务端日志显示"校验全通过"，玩家申诉无法自证，信誉崩塌。

**服务端拦截点**：会话用**服务端签发的高熵 token**，不认客户端 SID；每包身份与服务端会话表强绑定，checkCode 仅作格式校验、绝不当鉴权。

### 攻击链 I —— UGC 图片放大 GET / SSRF / IP 泄露｜受害方：玩家隐私、第三方｜烈度：中

**漏洞**：家族图标、联盟景点图、DIY 表情、庄园/市容装饰等 UGC 图片 URL 由服务端/其他玩家下发，客户端**无域白名单**直接 HTTP GET 并落盘渲染。

**利用步骤**：恶意族长/玩家放入自定义 URL → 所有可视范围内玩家客户端主动 GET → ① 对攻击者服务器造成 SSRF 探测（拿到玩家 IP、代理指纹）；② 下发超大响应耗尽玩家存储/带宽；③ 表情被聊天引用时每次拉取 → 对目标域名持续放大 GET（DDoS 反射源）；④ 恶意 PNG 触发底层解码器漏洞。景点系统触达面最广（联盟数百人浏览即拉取）。

### 攻击链 J —— 违禁内容传播（接收端无过滤）｜受害方：内容合规红线｜烈度：中高

**漏洞**：昵称/公会名/盟旗/聊天/邮件敏感词过滤只在**发送端** `UIUtil.BadWordCheck` 做；接收端仅海外版启用 `SensitiveFilter`，国服接收端不过滤（[ChatData.cs:3206](file:///Users/bytedance/stzb/stzb_9.2.2_out_branch_9.1.1776213/assets/decompiled/Game.Data.GamePlay/Tenth.Data/ChatData.cs)、[UIUtil.cs:6211-6243](file:///Users/bytedance/stzb/stzb_9.2.2_out_branch_9.1.1776213/assets/decompiled/Game.UI.Core/Tenth.UI/UIUtil.cs#L6211-L6243)）。

**利用步骤**：改包绕过本地 BadWordCheck → 发违禁内容 → 国服所有接收方即时展示。**直接触及内容合规红线，可能导致停服整改。**

**服务端拦截点**：敏感词过滤**前移到服务端广播出口**，接收端展示前不依赖客户端过滤；所有玩家可写文本入库前服务端复检。

### 攻击链 K —— DevMode 后门横向解锁｜受害方：私服控制权｜烈度：中高

**漏洞**：`GameConfig.DevMode` 是纯客户端布尔，写 UserDefault 即可开；开后解锁改服务器地址、GM 面板（口令 `g10#debug` 硬编码）、关实名、切功能解锁本地判定。

**利用步骤**：玩家开 DevMode → 拿 GM 面板 → 若服务端未对 GM 类命令（91001、GM 指令、98765）做账号级鉴权 → **普通玩家变 GM**。

**注意（收敛）**：功能解锁本地化被 DevMode 死门控——`IsFunctionUnlockUseServer()` 在非 DevMode 恒返回 true（[ConfigBeforeLoad.cs:787-793](file:///Users/bytedance/stzb/stzb_9.2.2_out_branch_9.1.1776213/assets/decompiled/Game.ConfigAndSdk/Tenth/ConfigBeforeLoad.cs#L787-L793)），且调用点多为 UI 面板显隐（MainUI 中多处），**解锁的是 UI 入口可见性，不等于能发未授权请求**。真正危害取决于服务端是否对被解锁功能背后的命令做鉴权。

**服务端拦截点**：所有 GM 类命令走独立账号白名单（服务端侧）；服务器地址不因客户端标志改变鉴权；DevMode 相关能力在正式环境服务端一律不认。

## 3. 设计正确、无需担心的点（避免误判）

审计中确认了几处"客户端算 ≠ 可利用"的正向设计，私服还原时可放心：

1. **时钟抗改系统时间**：`GameTime.ServerTime` = `Stopwatch` 单调时钟 + 服务端对时偏移，**不读 `DateTime.Now`**。玩家改手机时间无法加速 CD/提前签到（[GameTime.cs:18](file:///Users/bytedance/stzb/stzb_9.2.2_out_branch_9.1.1776213/assets/decompiled/Game.Core/Tenth.Data/GameTime.cs#L18)）。
2. **战斗全服务端权威**：服务端下发完整战报字符串，客户端无伤害/暴击公式，仅解析播放（[ReportDetailData.cs:315-493](file:///Users/bytedance/stzb/stzb_9.2.2_out_branch_9.1.1776213/assets/decompiled/Game.Data.GamePlay/Tenth.Data/ReportDetailData.cs#L315-L493)）。
3. **抽卡无本地随机**：`CardSummonData` 无任何 `Random`，结果由服务端下发。
4. **充值到账无客户端上报越权点**：货币只经服务端 `DbNotify` 下发，getter 只读（见攻击链 B 好消息）。

**结论**：不要把"客户端计算"一律当漏洞。真正的风险是"客户端只发意图 / 展示层预判 → 服务端不兜底"，以及"信任服务端与其他玩家的可控内容"。
