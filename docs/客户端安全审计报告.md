# 《率土之滨》9.2.2 客户端安全审计报告

- **审计对象**：`stzb_9.2.2_out_branch_9.1.1776213`（il2cpp 反编译 C# 源码 + APK 解包资源）
- **审计性质**：纯离线静态代码审计。目的是厘清客户端信任边界，反推权威服务端必须校验哪些环节。
- **审计范围**：网络协议层 / 鉴权层 / 反作弊层 / 收包解析健壮性 / 本地存储 / 资源与热更完整性 / 可信输入与越权 / WebView。
- **说明**：源码经混淆，部分符号被替换（如 `http://`→`n` 前缀、`DevMode`/`OpenWebView` 被改名），报告中已按完整上下文还原真实语义。native 层（引擎 so、UniSDK、易盾）不可反编译，相关结论标注为“静态层面未见”。

---

## 0. 一句话结论

该客户端在传输层与鉴权层几乎不提供任何密码学保障（XOR 混淆 + 无密钥校验和 + 可预测 SID + 仅判空的 Session），反作弊为可绕过的旁路上报，热更与本地存储缺乏完整性/机密性保护。**整套设计的隐含前提是“服务端做全部权威校验”**。因此私服还原可行；而任何加固的重心都在服务端侧。

## 2. 高危详情

### H1 — 收包长度字段无上限/非负校验（可远程崩客户端）

两处都把报文自带的长度直接拿去分配/读取，无任何边界检查。

**(a) 帧长度**
`Game.Network/Tenth.Network.AppSocket/SocketReceiveChannel.cs:345-346`
```
int msgLength = (buffer[0]<<24)|(buffer[1]<<16)|(buffer[2]<<8)|buffer[3];  // 有符号 int，可为负
await AppSocketReceiveCompleteAsync(buffer, msgLength, ...);                // 无上限/非负校验
```
接收缓冲区固定 5MB：`DotnetSocketReceiveChannelBase.cs:121 _receivedBuff = new byte[NetBuff.MAX_MSG_SIZE]`（`NetBuff.cs:11 = 5242880`）。
- `msgLength > 5MB` → `ArgumentException`（`SocketReceiveChannel.cs:369` 的 ArraySegment 越界）打断接收线程 → 断线/无限重连。
- `msgLength < 0` → 后续切片抛异常。

**(b) zlib 解压原始长度**
`Game.Network/Tenth.Network.BaseSocket/DotnetBaseSocket.cs:556-557`
```
byte[] array2 = new byte[netBuff.ReadInt()];   // dataType==3 时直接用报文里的原始长度分配
int num3 = ZipUtil.DecompressToTarget(msgBytes, netBuff.Cursor, msgBytes.Length - netBuff.Cursor, array2);
```
声明长度填 `0x7FFFFFFF` → 立即尝试分配 ~2GB → OOM 崩溃；负值 → `OverflowException`。`ZipUtil.DecompressToTarget`（`ZipUtil.cs:100-131`）按 target 定长写入，间接缓解了经典“zlib 炸弹”，但**声明长度本身无上限**这一分配 DoS 未防护。

- **危害**：高。下行仅 0x98 异或（见 H2），中间人可篡改长度字段；私服场景下发畸形 dataType=3 包可直接崩真机。
- **修复**：读长度后立即 `if (len <= 0 || len > MAX_MSG_SIZE) 主动断开`；解压前对声明长度做同样校验。
- **对私服的直接启示**：下发 dataType=3 包时必须保证 4B 原始长度准确合理，否则真机会崩——这也是联调要避开的坑。

### H2 — 传输层加密与完整性形同虚设

- **上行 body**：`DotnetBaseSocket.cs:323` 计算 `checkCode = (CmdIndex*13)^CmdId^UserId`；`:334 SetEncodeSeed((byte)checkCode, ...)` 用 checkCode 最低字节做 XOR 种子；`NetBuff.cs:73-83 Encode()` 整个 body 用同一单字节异或（无 IV/无链式）。而 CmdId/CmdIndex/UserId/checkCode 全部明文写在帧头（`:324-330`）——读帧头即可算出 key。
- **下行 body**：`DotnetBaseSocket.cs:563-569` `dataType==5` 时 `msgBytes[i] ^= 152`（0x98），固定常量，无动态因子。
- **checkCode 非 MAC**：下行解析 `DotnetBaseSocket.cs:507-591 ProcessBytesReceived` 只读 cmd/hashCode，**完全不校验 checkCode**；它是无密钥线性异或，只能防误码不能防篡改。
- **无 HMAC/nonce/防重放**：全库检索 `hmac/sign/nonce/replay` 网络层无命中；唯一“序号” `DotnetCmdMgr.cs:217 _cmdIndex++` 明文自增，不参与任何 MAC。

- **危害**：高。单字节 XOR 密钥空间仅 256，且 key 由明文推导 + body 是 UTF-8 JSON（已知明文攻击秒破）；录制包可重放；攻击者可对任意伪造上行包重算合法 checkCode。
- **修复**：AEAD 会话加密（握手协商密钥，一包一 nonce），机密性+完整性交给 AEAD tag；服务端按会话绑定校验 userId，不信任包内自带值；服务端侧序列号窗口去重 + 时间窗防重放。

### H3 — 热更补丁 / DLL 无签名校验（供应链注入，最高危路径）

- **补丁列表无完整性字段**：`Game/Tenth.Update/PatchDownloadHandler.cs:100-112 SplitPatchListFromStrConent` 仅解析 `ver/size/url`，**无 md5/hash/签名**。
- **下载后直接解压落盘**：`PatchDownloadHandler.cs:148-171 TryUncompress` 直接 `CCUtil.uncompress(...)`，无验证；`:235 CheckPatchContainsAssemblyMinimalDll` 检测到 DLL 补丁即触发重启加载（代码热更）。
- **DLL 差分热更无验签**：`MonoLoader/MonoLoader/PatchPlugin.cs:21-35 ApplyPatchRaw` → `ScriptingAssemblyPatcher.ApplyAssemblyBinPatch`，应用后直接 `WriteFile` 写盘（约 L84-105）。
- **URL 可被覆盖 + HTTP 降级**：默认 HTTPS（`PatchListParser.cs:308-328/520-546`，正面），但 `PatchListParser.cs:95-108` 从 patchlist 读取 `patchUrl/packUrl/retailUrl` 覆盖默认值；`GameUpdateBeforeLogin.cs:251` 存在 `http://stzb.163.com/index.html` 明文引导页；`ConfigBeforeLoad.cs:922-946 GetUpdateAddress` 可被本地 UserDefault `_Key_Update_Address_TMP_` 覆盖。

- **危害**：高。补丁/patchlist 传输被 MITM 或本地覆盖 URL + 无验签 → 任意代码注入。
- **修复**：每个补丁包非对称签名 + 逐包 hash 校验，验签失败拒绝加载；patchlist 与所有补丁强制 HTTPS + 证书固定；URL 覆盖字段仅在验签后的 patchlist 中生效。

### H4 — 账号密码明文落盘

`Game.Data.GamePlay/Tenth.Data/LoginData.cs`
- `:99 UD_KEY_USERNAME="_ud_key_user_name_"`、`:101 UD_KEY_PASSWORD="_ud_key_password_"`
- `:936-949 SetCachedAccountInfo`：`setStringForKey("_ud_key_password_", password)` 明文写入
- `:828-834 GetCachedAccountInfo`：明文读取
- 底层 `Game.Core/Tenth/UserDefault.cs:305/311` 落 cocos2d UserDefault 的明文 XML
- 项目内存在 `Game.Core/Tenth.Utils/EncryptUtil.cs`（DES/MD5/Base64）**但账号密码路径完全未调用**

- **危害**：高。该 XML 在应用私有目录，root/系统备份/模拟器共享目录场景可直接读到明文账号密码。
- **修复**：密码不落盘（改存 SDK token/refresh_token）；必须缓存则用 Android Keystore 派生密钥加密；服务端登录态以短时效 session 为准。

### H5 — 硬编码密钥/口令 + DevMode/配置后门

**硬编码凭证**
- 易盾 secretKey 各区明文：`Game.ConfigAndSdk/Tenth.Sdk/AntiSDKManager.cs:110-153`（国内 `gnxs5cui1btbqx9d` :142；HMT/AS/KR/JP :121-134）
- GM 后门口令：`Game.UI.GamePlay/Tenth.UI/GmEntryView.cs:37 == "g10#debug"`
- 反作弊白名单 RoleID（免检）：`AntiSDKManager.cs:40`（`2xbidf755564` / `2920943047` / `17x77yvo3986`）
- 平台校验固定值：`SdkManager.cs:558-559 gameid="g10"、login_channel="_stzb_test_"`

**配置/模式后门**
- `_game_config0.json` 探测即开内网：`Game.Core/Tenth/GameConfig.cs:881 IsInnerPackage => Cfile.FindResFile("csharp/_game_config0.json")`；`:924-985 Load()` 用其覆盖默认配置（含 DevMode/ServerIp/UpdateAddress）；`:533-543` 内网包 YouthServerIp 改写为 `10.147.36.168`。
- DevMode 本地可开：`GameConfig.cs:78 DevMode=true` 默认字段；`:285-300` getter 读 UserDefault `_Key_Dev_Mode_`，本地写 `"True"` 即开。
- DevMode 解锁能力：改登录服 IP/端口、改补丁地址、切换环境、跳 CG、关实名（`ConfigBeforeLoad.cs:391-401 IsSupportRealName`）、任意 GM 指令（`GMLoginCommandPanel` → `GMDispatcher.cs:130-196 OnDebugInput` 反射执行 `[GMCommand]`）。GM 入口手势见 `LoginMainUI.cs:1712-1788`，token 序列 `:4898-4937`（`[1,-1,-1,1,1,1,-1,-1]` = 左右右左左左右右）。

- **危害**：高。secretKey 可提取 → 伪造易盾上报参数；配合 H3 无完整性校验，塞入 `_game_config0.json` 即可开内网模式、改服务器地址、关实名。
- **修复**：secretKey/白名单移到服务端配置；发布包编译期硬关 DevMode 及 `_game_config0.json` 覆盖分支；实名/跳过等安全开关不受本地可写标志控制；GM 指令效果必须服务端账号级 RBAC 鉴权 + 审计日志。

## 3. 中/低危详情

### M1 — 反作弊仅旁路上报（易盾/Acsdk）
`Game.ConfigAndSdk/Tenth.Sdk/AntiSDKManager.cs:243-261 SendCheatContent` → `NetManager.Send<object[]>(191, msg)`，**只发送，不断线/不拦截**；`OnSetupSDK`/`OnCallSDK`（:225-241）异步上报。`NeeToOpen`（:36-51）iOS 恒 false、3 个白名单 RoleID 直接 false。
- **危害**：中。hook `SendCheatContent`、伪装白名单/iOS 平台即可整段关闭；上报字段可篡改（secretKey 硬编码）。
- **修复**：判罚在服务端；对“从未上报/上报缺失”的会话也计可疑；191 内容用服务端可验证签名校验。

### M2 — ServerSession 仅判空 + SID 可预测
- ServerSession：`SdkManager.cs:608 ServerSession=(string)val[2]` 直接取 99992 响应第 3 元素无验签；客户端唯一校验 `LoginMainUI.cs:4505-4534` 仅 `IsNullOrEmpty`；使用点 `LoginData.cs:3447/3676/5219/5693` 均只判空。
- SID：`DotnetCmdMgr.cs:352-363 GenUniqueSid` = 固定前缀 `^F#$G)*Ju7(E` + 负时间戳右对齐 20 位，明文随包发送。
- **危害**：中。SID 熵极低可预测；Session 信任边界完全在服务端。
- **修复**：服务端签发不可伪造 token（HMAC/JWT + 短过期 + 设备/IP/userId 绑定），后续每包校验；不把 SID 当凭据。
- **对私服的启示**：印证“99992 返回 `[1, null, ServerSession, userId]` 即可放行”的还原结论——握手返回合法结构即可，无需真实签名。

### M3 — WebView 下发 URL 直开 + customJS 注入
`Game.ConfigAndSdk/Tenth.Sdk/PlatformBeforeLoad.cs:194-505 OpenUrlByNgWebView`（走原生 `NGWebViewOpenURL`）；`:481-484` 支持 `customJS` 注入、`:486-489` 启用 localstorage。服务端下发直开：`LoginBulletListUI.cs:419-421`（公告富文本 `linkUrl[0]=='3'` 即 `OpenWebView`）、`:522/:680`。全流程无域名白名单。
- **危害**：中-高。服务端下发链接被篡改/伪造可加载不可信页面 + 注入 JS。
- **修复**：加载前域名白名单（限官方域）；customJS 仅允许内置固定脚本；JS bridge 限定可调用方法并鉴权。

### M4 — 下行 JSON 宽松反序列化 + 弱类型强转
`DotnetBaseSocket.cs:581 JsonUtil.Deserialize`；`JsonUtil.cs:47-57` `AllowTrailingCommas/IncludeFields` 宽松，解析为弱类型 object 树；业务层大量 `(int)val[0]`/`(string)val[2]` 强转（如 `SdkManager.cs:591-620`），畸形结构抛 InvalidCast/IndexOutOfRange。递归深度依赖 System.Text.Json 默认 64，但输入长度受 H1 无上限影响。
- **危害**：中。畸形下行可致类型混淆异常 / CPU-内存 DoS。
- **修复（反向启示）**：服务端解析上行 JSON 同样要设长度/深度/字段类型上限，不假设客户端发良构 JSON。

### M5 — 功能解锁可本地化 + 数值客户端可读写
`GmConfigView.cs:352-386 SetFunctionUnlockUseServer(false)` 可把功能/章节解锁切为本地判定（DevMode 下）；`AntiSDKManager.cs:90-91` extra_param 里 `power=UserData.ForcesPower`、`vip_level=UserData.RMBPaidNums` 由客户端提供。战斗伤害计算全库无独立 `CalcDamage/DamageCalc` 命中（倾向服务端结算，正面）。
- **修复**：解锁门控/资源/战力/冷却/移动合法性一律服务端权威判定，客户端上报当“请求”而非“结论”。

### M6 — 模拟器/root/hook 仅采集上报

- **修复**：服务端基于 191 做设备风险画像分级处置；对检测模块未初始化/回调缺失的会话加权。

### M7 — token 明文存储 / 本地存档无完整性校验

### M8 — GM 页面 token 拼 URL / GM 工具走内网 HTTP

## 4. 反推：权威服务端应校验的核心边界

1. **传输**：AEAD 会话加密替代 XOR；每包 HMAC/tag 校验完整性；序列号窗口去重 + 时间窗防重放。别信 checkCode。
2. **鉴权**：登录态以服务端短时效 session/token 为准（设备/IP/userId 绑定），不信任客户端缓存凭据/自报 userId/自报 SID。
3. **收包健壮性**：上行长度先做 `0 < len <= 上限` 校验再收；JSON 设长度/深度/字段类型上限；畸形包主动断开而非崩溃。
4. **业务权威**：good_id→价格/发货、道具数量、抽卡结果、战力/VIP/资源、解锁门控、移动/冷却，全部服务端权威判定，客户端值仅作展示。
5. **GM/风控**：GM 命令独立命令段 + 账号级 RBAC + 审计日志；反作弊 191 缺席也计可疑。
6. **热更/资源（针对官方客户端加固）**：补丁/DLL/配置强制服务端签名 + 客户端验签，HTTPS + 证书固定；移除 `_game_config0.json` 运行期覆盖后门；发布包硬关 DevMode。
