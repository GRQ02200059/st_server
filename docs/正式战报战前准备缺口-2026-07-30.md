# 正式战报战前准备阶段缺口

## 对比样本

- 正式完整战报：`assent/cfg/paper/11/cap_20260312014510506_0000000b_zlib.json`
- 当前实现：`ClientBattleTextReplayAdapter` 生成的同规模六武将战报
- 正式样本首回合 `091` 前有 625 条动作；当前样本首回合前只有 147 条。
- `paper/11` 与 `paper/6231` 的 `report` 都是明文 `#` 分隔动作串，外层 JSON 已由抓包工具解压。

## 已确认的缺口

### 1. 武将初始化数据不完整

正式 `5p`（十进制 205）记录包含：

`位置,等级,初始兵力,三组战法ID/等级,两组兵种特性,装备槽及装备等级等扩展字段`

当前实现只写：

`位置,等级,初始兵力,三组战法ID/固定等级1,0,0`

因此缺少真实战法等级、兵种特性、装备/宝物数据以及其他尾部扩展字段。

### 2. 六名武将的初始属性展示完全缺失

正式样本在通用加成阶段按双方逐将输出攻击、防御、谋略、速度等属性变化及变化后的数值，例如 `19/1a/1b/1c` 动作族。当前协议表没有这些动作，适配器也从未输出 `BattleHero.stats`。

### 3. 通用战前加成流水缺失

正式样本在被动与指挥战法前还有多段初始化：

- `0k + 295xxx`：通用战斗规则/基础加成；
- `5s + 291xxx`：阵营或组合类加成；
- `7x + 296xxx`：兵种、阵营、赛季等附加效果；
- `ba + 400xxx/450xxx`：装备及装备特性。

这些阶段会逐目标写入属性、增减伤、状态、持续回合或层数。当前战报没有对应阶段；Builder 中即使已经把一部分静态加成算进最终属性，客户端也看不到“由什么带来多少变化”。

### 4. 被动、指挥、主动动作码映射错误

正式样本显示：

- `0l`（21）：被动战法；
- `0m`（22）：指挥战法；
- `0n`（23）：主动战法；
- `0o`（24）：追击动作族。

当前实现把被动和指挥都编码为 23，把主动编码为 22；这会让战前准备的战法类型和展示阶段错位。

### 5. 指挥/被动战法只报“发动”，不报完整附属值

当前 `StatChanged` 只输出一次 `skillCast(target, skillId)`，丢弃：

- 属性类型；
- 增减值；
- 变化后的属性值；
- 持续回合；
- 来源与目标之间的归属。

`StatusApplied` 也没有完整输出 `power`、`durationRounds`、`statDelta`。正式样本会继续输出 `ja`、`0s/0t`、`1x` 等动作，携带效果 ID、目标、数值、回合或层数。

### 6. 派生战法和根战法关系丢失

正式战报会区分主战法与 `210xxx/211xxx/212xxx/213xxx` 派生效果。引擎事件虽然有 `rootSkillId`，适配器只使用 `skillId`，无法完整还原“战法发动—附属效果—目标变化”的层级。

### 7. 效果生命周期表达不完整

当前仅覆盖少量状态施加、移除和阻挡动作。以下内容没有完整投影：

- 效果冲突、覆盖与刷新；
- 层数变化和最大层数；
- 增伤、减伤、受到伤害变化的具体百分比；
- 规避、洞察、先手、连击等概率或持续值；
- 装备特性、兵种特性及阵营加成的来源；
- 战前目标选择和被影响目标列表。

遇到未支持效果时，安全模式只记录服务端 warning，并从客户端战报中省略，因此客户端看到的准备阶段会比真实结算少。

## 建议补全顺序

1. 先建立正式的战前阶段模型，保留战斗开始时每名武将的原始属性快照和每次效果应用后的数值。
2. 修正 `21/22/23/24` 四类战法动作映射，严格区分被动、指挥、主动、追击。
3. 完整实现 `5p` 武将信息：真实战法等级、兵种特性、装备及特性。
4. 补齐属性变化动作：来源、目标、属性/效果 ID、变化值、变化后值、持续回合和层数。
5. 再补通用规则、阵营/组合、兵种、装备四个战前阶段。
6. 最后按正式样本补效果覆盖、冲突、移除和特殊赛季动作。

在这些完成前，当前回放可以表达基础战斗过程，但不能视为正式战报的完整战前准备回放。

## 本轮已补全

- `5p` 已扩展为固定 19 字段，支持三组战法及等级、两组兵种特性、三组装备及等级；玩家和 NPC 战法等级已接入现有业务中的 10 级数据。
- 战斗结果保留双方入场快照，初始化字段不再误用战斗结束后的属性或兵力。
- 六名武将会输出攻击、防御、谋略、速度初始值。
- 被动、指挥、主动、追击分别使用 `0l/0m/0n/0o`。
- 属性增加使用 `19/1a/1b/1c`，属性降低使用 `1g/1h/1i/1j`，包含来源、战法、目标、持续、变化量和应用后值。
- `ja` 已按正式样本输出效果强度，不再误写持续回合。
- 战前正面/负面状态使用 `0s/0t`；属性型 `StatusApplied` 不再与完整属性变化重复输出。
- 根战法继续使用四类发动动作，`210xxx/211xxx/...` 派生效果改用 `8c`。
- JSON 战报保留 `StatChanged.effectId/valueAfter`、`ModifierApplied`、`StatusApplied.power/statDelta`。
- 已增加真实引擎集成用例，覆盖魏武之世、大赏三军、神兵天降在首回合前的完整字段。

## 仍待业务数据或更多样本确认

- 玩家状态目前没有兵种特性、装备槽及装备等级的持久化来源，因此字段结构已支持，但真实玩家战报仍会以空值填充这些槽。
- Builder 已把阵营、营地、装备静态属性算进入场属性，但尚未保留每一项静态加成的来源流水，无法完整生成正式样本中的 `0k/5s/7x/ba` 阶段。
- 效果覆盖、刷新、冲突、层数及部分赛季特殊动作仍缺少统一的战前事件模型。
- 攻城和攻击距离没有在已核实样本中确认与当前协议动作的一一对应关系，暂未冒充四维属性输出。
