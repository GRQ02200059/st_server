## 0. 一句话结论

**最重要的是一个排除项:充值/真金白银发货没有"客户端声明金额"的问题。** 这是最高价值的确认——重新审了整个支付面,游戏服务器**从不被告知客户端声明的 SKU/价格/金额来发货**。下单只把 `good_id + 配置名 + 数量` 交给 SDK,价格字段(rmb/jpy/krw/vnd)只用于本地限额弹窗、从不作为权威发给游戏服。首充/月卡奖励(886/4880/3690/325/326/995)发空包或只发 activityId,由服务端定价。

新增 **3 条**(+1 低置信),都是之前没审过的命令上的资格/授权标志:🟠 建造/升级(cmd 13/14)带客户端 isFree 免费标志、🟡 武将迁徙(cmd 75)客户端发授予的技能、🟡 聊天(cmd 710)客户端发跳过冷却标志。

**四轮之后,这个面基本扫干净了。** 高价值套路(资格标志、uid 可推的冗余服务端值、客户端算的数量)都已刻画完;剩余未读的 Send 绝大多数只带意图(id/目标/数量),服务端重定价。不建议再做宽泛的第五轮。

## 1. 🏗️ cmd 13/14 建造/升级:客户端 isFree 免费标志上包 【HIGH】

- **计算**:`BuildConstructInfoUI.cs:647` `int isFree2 = ((!isFree) ? 1 : 0);`(镜像 `BuildMsgUI.cs:1193`)。
- **发送**:`PoliticsData.cs:1493` `obj2.Add(isFree)`,`:1497` `Send<List<int>>(14, obj2)`;建造 `:1519` `Send<List<int>>(13, obj)`。cmd 14 包体 = `[wid, buildId, isFree, iTargetLv, 0, needQuickBuild]`,**isFree 在第 3 位**。
- **利用**:改包客户端把 cmd 13(建造)/14(升级)第 3 位翻成免费值。若服务端按此标志分支建造成本 → **每座建筑免费建/升**。和已确认的 851 迁城 mIsFree 同类,只是落在没审过的建造命令上。
- **注意**:出厂路径都发 0,所以服务端**可能已经自己持有免费判定并忽略此标志**——但仅凭客户端代码无法确认。**建议实测:发 cmd 14 时把第 3 位置为免费值,看服务端是否真免扣资源。**
- **服务端必须**:**无视客户端第 3 位 isFree**,按建造时间配置+玩家权益重算免费/立即资格,一律全额扣资源+金;第 4 位 iTargetLv 按等级重定价;第 6 位 needQuickBuild 校验加速道具拥有再消耗。

## 2. ⚔️ cmd 75 武将迁徙(点姬/点仓):客户端发授予的技能 skill_init 【MED】

- **计算**:`MaterialDetailUI.cs:1532` `int skill_init = HeroCfgData.GetHeroCfgInfo(mHeroCfgID).skill_init;`(读客户端静态配置)。
- **发送**:`:1533` `Send<object[]>(75, new object[3] { heroUidByCfgID, skill_init, false }, OnTraveled)`。skill_init 在 slot[1],**是 heroUid 的纯函数、服务端本可自己推**。
- **利用**:改包在 slot[1] 塞任意 int。若服务端按客户端 skill_init 授技而不是按武将自己的 cfgId 重推 → **武将获得它本不该有的技能**。客户端门禁(CheckIsOldPlayerAndHasDianjiCard、CanTravel)不约束包里的值。
- **服务端必须**:**无视 arg[1]**,自己按 `cfg[heroCfgIdOf(arg[0].heroUid)].skill_init` 重推、只授这个;迁徙资格(持点姬/点仓卡、func-state==2)服务端重校验。

## 3. 💬 cmd 710 / 27048 聊天:客户端发跳过冷却标志 isIgnoreCD 【MED】

- **计算**:`ReportMultiShare.cs:1633` `int isIgnoreCD = ((reportDataList.Count > 1) ? 1 : 0);`——**客户端自己决定这条聊天能否跳过发送冷却**。
- **发送**:`ChatData.cs:3065` `obj6.Add(isIgnoreCD)`,`:3093` `Send<object[]>(710, new object[11]{ ..., isIgnoreCD, ... })`(index 8);也走 cmd 27048(47 频道沙盒聊天)。正常发默认 0,只有批量分享置 1——所以这功能**只在服务端认这个标志时才生效**。
- **利用**:改包每条 RequestChat 都硬置 isIgnoreCD=1 跳过每条冷却 → **世界/军团/私聊无限刷屏**。反刷屏绕过,无直接经济收益。
- **服务端必须**:**无视 index 8 的 isIgnoreCD**,服务端权威 enforce 每发送方/每频道冷却;只对服务端计数确认的多战报批量给冷却豁免,绝不认客户端布尔。

## 4. 🃏 cmd 300 换卡开关:发送服务端持有的 switch_count_rotate 计数 【LOW · 低置信】

- `CardOpRequest.cs:1276` `int switch_count_rotate = CardSummonData.GetExtractCardInfo(extractCardUID).switch_count_rotate;`,`:1277` `Send<object[]>(300, new object[3]{ extractCardUID, switch_count_rotate, switch_count })`。该计数是同步的 Tb_* 字段,服务端可由 extractCardUID 自己恢复。
- **低置信**:若服务端按客户端 switch_count_rotate 定下次换卡(递增)成本,发低值/0 就付最便宜档;但它也可能只是乐观并发的版本比对令牌,仅凭客户端代码分不清。列出只因它和已确认的 skill_init 完全同类(冗余、服务端持有、按 uid 键、确实上包)。
- **服务端必须**:无视 arg[1],按 extractCardUID 重载权威换卡计数定价;客户端值最多当过期版本检查、绝不当成本依据。
