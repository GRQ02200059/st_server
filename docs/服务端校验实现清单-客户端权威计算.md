# 服务端校验实现清单 — 客户端权威计算

> 生成日期 2026-07-27。把四轮[客户端权威计算审计](客户端漏洞审计-2026-07-27-客户端权威计算.md)的 **23 项 + 1 低置信**整理成给服务端开发直接照做的清单:每条列 **cmd / 忽略哪个字段 / 服务端重算什么 / 拒绝条件 / 严重度 / 出处**。所有引证见对应轮次报告。

---

## 通用原则(适用于所有 cmd)

1. **`GameTime.ServerTime` 客户端可轻易伪造**(`GameTime.cs:12` 的 `ServerTimeDiff` 是 public 可写字段)。→ 所有时间判定(冷却/免费资格/到期/重伤/产出累积)**只认服务端时钟**,绝不用客户端时间或 `xxx_end_time > 客户端ServerTime` 的结果。
2. **客户端发来的每个值都当"参考/意图",不当权威**:成本、金额、资格标志、随机结果、数量、计数——一律服务端独立重算。
3. **只信 id/目标,不信派生值**:heroUid/buildId/targetWid/shopItemId 这类"选择"可接受(仍需校验合法性/拥有权);cost/amount/discount/rng-result/eligibility-flag 这类"派生值"一律重算。
4. **扣款原子化**:先校验权威余额 ≥ 需扣量,再原子扣正好的量;不足即拒绝。绝不按客户端声明的量入账。
5. **动作按服务端状态重新门禁**:冷却/次数/每日上限/前置条件在服务端 enforce,不依赖客户端置灰按钮或本地门禁(IsHeroInHurt / IsInSummonCodeCD / mLeftPoints 等都是仅供 UI,可绕过)。

## 落地方式建议

对每个 cmd 的 handler,加一层**输入规范化**:进 handler 后立即把上表"忽略字段"从请求里丢弃(或标记为 untrusted),只保留 id/目标类字段;业务逻辑一律从服务端权威状态取值。这样即使后续新增调用点,也不会误信客户端派生值。

一个**通用测试**:对每个 cmd 写一个"恶意客户端"用例——把忽略字段填成最有利的值(免费/最大/最稀有/已完成),断言服务端行为与"字段填正常值"完全一致(该扣的扣、该拒的拒)。这 24 条各一个用例,就是这套防线的回归基线。
