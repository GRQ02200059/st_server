> 生成日期 2026-07-27。专项主题:**客户端自己算的玩法关键值/时间/门禁,服务端哪些不能信、必须自己重算**。这是上一版[独立复核](客户端漏洞审计-2026-07-26-独立复核.md)(网络/GM/WebView/加密)没系统覆盖的一类。

## 0. 一句话结论

**先答你问的"重伤时间自己计算":这个例子恰恰是设计正确、安全的。** 重伤结束时间 `hurt_end_time` 是**服务端下发的字段**,客户端只拿它跟 ServerTime 比较判断"还在不在重伤"、**从不发送**。兵力恢复、事务、探索、寿命时间全是同一个安全模式。

**但你指的方向是对的,而且命门确实塌了:** `GameTime.ServerTime` **可被客户端轻易伪造**——它就是个静态字段的 getter,偏移量 `ServerTimeDiff` 是 **public static 可写字段**(赋值即可,连 IL patch 都不用)。后果:**所有 `xxx_end_time > ServerTime` 的客户端门禁都能本地绕过**(提前触发定时动作)。

这本身不直接危害服务端——**只要服务端对每个动作用自己的时钟重新判定就行**——真正的危险在**客户端算完并发上去、服务端可能直接信的那 5 个值**。诚实结论:这个面**绝大多数是"只显示、安全"的**(建造/科技/征兵完成、行军到达、兵力、士气、战力、阵法合法性都是服务端权威),真正"发上去且服务端会信"的就 5 条,不注水。

## 1. 命门:GameTime.ServerTime 可被轻易伪造(yes-trivial)

`Game.Core/Tenth.Data/GameTime.cs`(已手工核对):

```csharp
:10  private static long sServerTime = 0L;
:12  public static double ServerTimeDiff = 0.0;                 // ← public 可写!
:16  public static long ServerTime => sServerTime;              // 只是字段 getter
:18  public static double RealServerTime => Stopwatch.GetTimestamp()*SecondsPerTick + ServerTimeDiff;
:90  sServerTime = (long)RealServerTime;                        // 每帧重算
:95  ServerTimeDiff = value - Stopwatch.GetTimestamp()*SecondsPerTick;  // DoSyncServerTime
```

- 基于 **Stopwatch(单调时钟)+ 客户端持有的偏移**,不绑墙钟——所以**改设备系统时间没用**,但改包客户端有多条独立、trivial 的手段:
  1. patch getter 返回常量;
  2. **直接给 public 字段 `ServerTimeDiff` 赋值**(每帧 `+= it` 会保持);
  3. no 掉 `DoSyncServerTime` / 丢弃 cmd 694(60秒一次)和 cmd 25 的重同步回复,让服务端的周期性重推无法覆盖伪造的偏移。
- 内置的"防呆"守卫(`UserData.cs:5804`,`|RealServerTime - ServerTime| > 1200 → InvalidSid`)**不权威**:它只拿客户端自己的两个派生值互比,一致平移即可通过,改包客户端直接删掉。
- 同步回复本身**未认证**。

**解锁了什么**:每个客户端侧 `end_time > ServerTime` 门禁(治疗/重伤恢复/征兵/建造/科技冷却/体力回复/事务)本地可绕(提前触发),且任何 ServerTime 派生、客户端**会发送**的值可被灌大。缓解事实:几乎没有时间派生值真的上包——服务端握着权威时间戳——所以伪造大多只换来"显示变化 + 本地门禁绕过",服务端必须(且结构上能)重新判定。**唯二**客户端算完真的上线的见 §2。

## 2. 真正危险的 5 条(客户端算 + 发上去 + 服务端可能信)

### 🟠 高危

#### #1 cmd 301 抽卡免费/付费标志(SummonState)—— 无限免费抽卡

- **计算**:`CardSummonData.cs:2188` 客户端用 `GameTime.ServerTime - free_time >= free_interval_cd` 自己判定这次抽卡是否免费;半价档 `CardSummonData.cs:590`。`CardOpRequest.cs:761` `summonState = SummonState.Free;`(Free=0/Half=1/Normal=2)。
- **发送**:`CardOpRequest.cs:830-838` `Send<object[]>(301, new object[9]{ summonCfgID, summonUID, summonOpType, num4, (int)resType2, childCfgID, (int)summonState, num2, num5 })` —— **第 6 位就是客户端算出的 summonState**。
- **利用**:改包客户端每次硬写第 6 位 = 0(Free)。若服务端按客户端的 summonState 计费/分支,则**免费冷却被跳过 → 无限免费抽五星**(最值钱的付费动作)。
- **服务端必须**:**无视 cmd 301 第 6 位(summonState)和第 4 位(resType2 不能作为唯一扣费依据)**;按服务端自己的 `Tb_user_card_extract`(free_time/used_count_free/free_count)+ 自己的时钟重算免费/半价/付费,再扣资源。

#### #2 cmd 5058 征兵后自动行军时长(planMoveTime)—— 队列行军瞬间到达

- **计算**:`ArmyMoveConfirm.cs:7273-7274` `long item2 = mHelper.GetArmyMoveDisInfo().Item4; mPlanMoveTimeAfterRecruit = (int)item2;` —— 纯客户端 `距离/速度`(含夜间/政策加成);`ArmyMoveConfirmHelper.cs:3367` 证明它是时长(`GetArriveTime = ServerTime + Item4`)。
- **发送**:`ArmyOpRequest.cs:134` `obj3.Add((object)planMoveTime)` 嵌进 cmd 5058 包发上去;经 `RequestBattle`(:239)在 plan-after-recruit 分支进入(此时**普通 cmd 6 被跳过**)。
- **利用**:发 `planMoveTime=0` → 征兵完成时那段队列行军**瞬间到达**,无视真实距离/速度。叠加可伪造的 ServerTime。**判别关键**:普通行军 cmd 6 **完全不带时间字段**,只有 cmd 5058 这条队列路径把客户端行军算术送到服务端。
- **服务端必须**:**无视客户端 planMoveTime**;计划触发(征兵完成)时,按权威路径距离 × 服务端侧军队速度(含夜间/政策)+ 服务端时钟重算到达时间。planMoveTime 最多当显示提示。

### 🟡 中危(客户端算的上限/数量上包,服务端不夹取就出问题)

#### #3 cmd 61 / 9062 预备兵携带数(redifNum)

- **计算**:`UserCityData.cs:1212` 可用预备兵 = `redif_cur + (ServerTime - redif_time)*100/redif_add`,夹到 `redif_max`;`RedifCarryUI.cs:162` 用它当滑条上限 `mMaxNum`。
- **发送**:`ArmyOpRequest.cs:761` `obj.Add(redifNum); Send<List<int>>(61, ...)`;`:1057` `Send(9062)`(RequestHangXingForArmy)。(采集 cmd 61 第 2 位、9062 第 4 位)
- **利用**:伪造 ServerTime 抬高外推预备兵 → 抬高上限与可发的 redifNum。若服务端按声明的携带数入账,则**多带出实际没攒够的预备兵**(受 redif_max 约束)。
- **服务端必须**:处理时按 `redif_cur/redif_time/redif_add`(+训练预备)用**服务端时钟**重算可用预备兵,夹取/拒绝客户端 redifNum。

#### #4 cmd 3981 赛季资源援助量(mTradeValue)—— 资源复制

- **计算**:`InviteSeasonAidGiveUI.cs:431` 滑条上限取自客户端可伪造的 `PoliticsData.GetResNumsByType(...).CurNums`;`:666` `mTradeValue = (int)(可用量 * 滑条%/100)`。
- **发送**:`InviteSeasonAidGiveUI.cs:721-727` `Send<object[]>(3981, { recipientUserId, { resTypeId, mTradeValue } })`。
- **利用**:客户端抬高滑条上限、发灌大的 mTradeValue。若服务端按声明的援助量给对方入账而不查自己账本 → **资源凭空复制**。
- **服务端必须**:把 mTradeValue 夹到发送方**服务端重算的权威余额**,超出即拒绝/截断;只按服务端权威量扣发。

#### #5 cmd 304 快速抽卡次数(quickCount)—— 单请求超抽

- **计算/发送**:`QuickSummonUI.cs` 客户端算上限 `mMaxNums`(本地缓存资源),`CardOpRequest.cs:920` `Send<int[]>(304, new int[7]{ summonUID, ..., quickCount, ... })` —— quickCount 是原始客户端值。唯一门禁是本地 10 秒节流 `IsInSummonCodeCD`(`CardOpRequest.cs:669`,基于可伪造 ServerTime)。
- **利用**:发任意 quickCount(绕过本地 mMaxNums 夹取和 10 秒节流)。若服务端不按真实拥有的抽卡货币夹取 → **单请求超量抽卡**。
- **服务端必须**:按玩家**服务端侧**拥有的免费/付费抽卡货币夹取 quickCount;用服务端自己的频率限制,而非信 IsInSummonCodeCD。

## 4. 服务端重算清单(按 ROI 排序)

1. **cmd 301(抽卡)**:无视第 6 位 summonState、第 4 位 resType2;按服务端 got_time/free_time 账本 + 自己时钟重算免费/半价/付费再扣费。**封无限免费抽卡。**
2. **cmd 5058(征兵后计划行军)**:无视嵌套 planMoveTime;计划触发时按权威距离/军速/夜间/政策 + 服务端时钟重算到达。**封队列瞬移。**
3. **cmd 61 / 9062(采集/航行携带预备兵)**:服务端时钟重算可用预备兵(clamp 到 redif_max 减已带),夹取/拒绝客户端 redifNum。
4. **cmd 3981(赛季援助/资源转移)**:把 mTradeValue 夹到发送方权威余额,超出拒绝/截断。**封资源复制。**
5. **cmd 304(快速抽卡)**:按服务端拥有的抽卡货币夹取 quickCount + 服务端频率限制。
6. **所有定时门动作**(hurt/hp/affair/explore/life end_time;出征/完成 cmd 6/193/1671/1673/1675 等):按**服务端侧** `*_end_time > 服务端时钟` 拒绝;**绝不依赖客户端的 IsHeroInHurt/CanHeroMove 门禁**(仅参考,伪造 ServerTime 即绕过)。
7. **cmd 6 / 61 的 intent flag**:校验 attackTechDetail(科技真研过)、fortShare、useSpeedup(道具真拥有)、redifNum(≤军队真实兵力)。
8. **cmd 64 backAtOnce 及所有 useSpeedup=1**:校验引用的加速道具真拥有/可消耗。
9. **cmd 6416 / 4099(集市/土地采集)**:按服务端时钟 + 产出配置重算累积量,只按服务端算出的量入账(包里只有 id,伪造 ServerTime 提前触发也应累积为 0)。
10. **服务端时钟卫生**:绝不接受客户端 ServerTime 或任何客户端派生时间作权威;cmd 694/25 同步路径对信任决策无影响——该字段完全攻击者可控。

## 5. 覆盖范围与方法

- **6 个玩法域**:重伤/兵力恢复/体力、行军/采集、建造/科技/征兵、资源产出、冷却/次数门禁、战斗战力/伤亡。命门(ServerTime)单独一路先判。
- 首轮 build/科技/征兵那一路因连接中断挂掉,已 resume 补跑覆盖,结论:该域**全是显示型安全**(完成时间服务端权威)。
- 综合环节两轮判断不完全一致(第二轮把 #3/#4/#5 错误降级),本报告不盲信综合,直接采用**通过对抗核实的 survivor + 本人手工二次核对的发送点**,故 5 条全部保留。
- 头条(#1 #2)、命门、以及 #3/#4/#5 的发送点、"重伤=服务端权威"均经本人手工核对源码,引证准确。
- **置信度边界**:本审计判定的是"客户端发什么";"服务端会不会信"取决于你们服务端实现——上面每条 server_must 就是让它不信的具体做法。原生层(.so)不在范围。
