# 主城地图可视化设计

## 目标

仅修改服务端，使每个玩家的主城在世界地图上创建完整、可见的城池模型，而不是只显示九格归属或空地。登录快照和后续 `5026` 世界视野刷新必须产生一致结果。

不修改、不注入、不部署客户端代码。

## 根因

客户端收到 `5026` 的主城条目后，仅当下列数据完整时才创建 3D 城池：

- `facade`：经客户端 `MapCityData.ChangeIndexWithServer` 解析的城池布局。
- 城建布局字段：客户端保存为 `MapCityBuildData`，非空时才调用 `AddCityTask` 创建模型。

当前服务端对这两个字段都下发空字符串，因此客户端跳过模型创建。

此前默认启用的 `111213` 是普通建筑外观，不是城主府。官方登录快照中，标准城主府使用：

- `build_facade_id = 113305`
- `belong_wid = cityWid`
- `active_wid = cityWid`
- `active_pos = 50005`
- `is_season = 1`

## 协议设计

新增主城视觉常量，内容来自 `assent/cfg/paper/99991/cap_20260312230336552_00018697_zlib.json` 中的有效官方主城记录：

- 服务端格式的完整城池 `facade` 字符串。
- 对应的非空 `facade3d` 城建等级字符串。
- 城主府 `113305` 的默认位置 `50005`。
- 标准城墙 `129901` 的默认位置 `0`。

该常量仅描述客户端已存在资源的布局，不包含玩家姓名、坐标或客户端补丁。

### 登录快照 `99991`

`Tb_world_city` 的主城中心行写入：

- 字段 3 `facade`：完整默认城池布局。
- 字段 4 `facade3d`：完整默认城建等级字符串。

副格、普通土地仍保持空布局。

`Tb_user_build_facade` 的所有主城外观记录绑定到该玩家主城：

- `belong_wid = cityWid`
- `is_season = 1`

其中城主府 `113305` 设为激活状态：

- `active_wid = cityWid`
- `active_pos = 50005`

城墙 `129901` 同样激活在 `active_pos = 0`。其他外观保持未激活，以继续表示“已拥有”。

### 世界场景 `5026`

主城中心的 `WORLD_CITY` 数组同步写入：

- 索引 5：与 `Tb_world_city.facade` 相同的城池布局。
- 索引 13：与 `Tb_world_city.facade3d` 相同的城建等级字符串。

副格和普通土地继续发送空字符串，避免把完整城池重复渲染到九格中的每一格。

## 代码边界

- `FacadeCatalog.kt`：保管经验证的主城府、城墙、布局和城建数据常量。
- `UserInitTableBuilder.kt`：构造登录快照中的主城视觉状态。
- `GameResponses.kt`：构造 `5026` 中同一主城视觉状态。
- `UserInitTableBuilderTest.kt`：验证 `99991` 表字段和城主府激活位置。
- `GameResponsesTest.kt`：验证 `5026` 的主城含非空布局与城建数据，而副格不含。

不引入持久化字段。主城视觉是所有账号统一的默认显示状态，由已有的主城坐标驱动。

## 错误处理

- 不使用客户端内部的纯文本布局替代服务端编码；只使用已在官方快照中验证的服务端格式。
- 不将布局写给副格或普通土地。
- 不改变现有建筑等级、土地归属、行军、武将或卡框数据。

## 验证

1. 新增测试先验证当前快照与 `5026` 缺少视觉字段时失败。
2. 实现后，登录快照主城行的 `facade` 与 `facade3d` 均非空，副格保持为空。
3. 实现后，`113305` 的 `belong_wid`、`active_wid` 和 `active_pos=50005` 与官方记录一致。
4. 实现后，`5026[14][cityWid]["0"][5]` 和 `[13]` 与登录快照主城行一致。
5. 运行定向 Kotlin 测试、构建发行包、校验部署 jar 的 SHA-256，并通过 ADB 抓取修复后的画面。
