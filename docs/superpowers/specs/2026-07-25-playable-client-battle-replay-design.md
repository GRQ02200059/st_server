# 高置信战斗规则与可播放客户端回放设计

## 目标

让客户端战报详情能够播放一场由服务端战斗结果动态生成的基础战斗：

- 攻守双方都会行动。
- 普通攻击有完整动作段和伤害结算。
- 主动战法有完整动作段，并能展示伤害、恢复和状态效果。
- 回合开始、战斗结束和最终兵力继续正常显示。
- 不依赖复制某一条固定真实战报。
- 修正攻击距离、主动战法与普通攻击时序以及三类控制状态语义。

本阶段不实现追击战法、装备动画、复杂准备阶段和所有特殊赛季效果。
本阶段不拟合客户端未公开的权威伤害公式；现有伤害公式保持不变。

## 战斗规则修正

### 攻击距离

双方阵型在战场上的基础距离为：

```text
distance = 5 - sourcePosition - targetPosition
```

其中双方内部位置均为：

- `0`：大营
- `1`：中军
- `2`：前锋

因此前锋对前锋距离为 `1`，大营对大营距离为 `5`。普通攻击只选择 `distance <= hitRange` 的存活目标，并优先选择距离最近的敌方武将，即敌方前锋、中军、大营。

### 单回合行动时序

未被混乱控制的武将按以下顺序行动：

1. 若未处于犹豫，尝试发动主动战法。
2. 无论主动战法是否发动或进入准备，只要未处于怯战，继续尝试普通攻击。
3. 普通攻击命中后尝试发动追击战法。

主动战法不替代普通攻击。准备战法进入准备状态也不替代普通攻击。

### 控制状态

- `CONFUSION`（混乱）：本阶段按无法行动处理，不释放主动战法、不普通攻击。
- `HESITATION`（犹豫）：仅禁止主动战法，仍可普通攻击和触发追击。
- `DISARM`（怯战）：仅禁止普通攻击，因此也不会触发依赖普攻的追击；仍可释放主动战法。
- `INSIGHT`（洞察）：继续阻止上述控制状态的施加。

本阶段不实现暴走的随机敌我目标、挑衅和围困。

## 已确认的客户端机制

`BattleAnimationData.SetRoundData` 不是把每条伤害记录直接加入动画队列。客户端需要先收到动作段开始标记，才会将后续 action 聚合到一个可播放的 `BattleDataCls`：

- `222`：普通攻击动作段开始，客户端建立 `begin = 2` 的动画段。
- `223`：普通攻击动作段结束。
- `213`：战法动作段开始，客户端建立 `begin = 5` 的动画段。
- `214`：战法动作段结束。

服务端当前直接下发伤害、恢复和状态 action，缺少这些开始/结束标记，因此文字数据虽然能被解析，动画队列却没有完整动作。

## 协议序列

### 普通攻击

每个 `BattleEvent.NormalAttack` 输出：

```text
222 普攻段开始
62  普攻伤害
223 普攻段结束
```

伤害 action 保留当前参数：

```text
targetPosition, sourcePosition, 0, damage, targetTroopsAfter
```

### 主动战法

同一次技能施放产生的事件输出：

```text
213 战法段开始
301 战法施放
60/63/102/59 伤害、恢复、状态或持续伤害
214 战法段结束
```

服务端需要按“施法者 + 技能 ID + 回合内连续事件”聚合，同一次施法只创建一个动作段。若现有战斗事件无法可靠表达聚合关系，则第一阶段允许每个技能效果各自形成一个完整战法段，优先保证客户端可播放与数据安全。

### 其他事件

- `9`：回合开始，保留现有行为。
- `14`：武将名称，保留现有行为。
- `205`：武将详情初始化，保留现有行为。
- `13`：战斗结束，保留现有行为。
- `224`：最终兵力，保留现有行为。
- 无技能 ID 的恢复或持续伤害不生成战法动作段，避免客户端引用不存在的战法。
- 规避和属性变化仅在能够归属到有效技能时加入战法动作段；否则留待后续阶段。

## 模块调整

### `BattleEngine`

- 使用正确的阵型距离和最近目标顺序。
- 将主动战法、普通攻击、追击从互斥分支改为顺序阶段。
- 分别判断混乱、犹豫、怯战，不再使用统一的 `shouldSkipAction`。
- 保持速度排序、伤害公式、持续伤害和战斗胜负逻辑不变。

### `ClientBattleTextReplayProtocol`

集中声明动作段常量：

- `NORMAL_ATTACK_BEGIN = 222`
- `NORMAL_ATTACK_END = 223`
- `SKILL_BEGIN = 213`
- `SKILL_END = 214`

### `ClientBattleTextReplayAdapter`

增加两个内部转换接口：

- 普攻事件转换为完整普通攻击动作段。
- 技能效果转换为完整战法动作段。

攻击方和防守方共用相同转换逻辑，位置仍通过 `ClientBattleTextReplayProtocol.position` 映射：

- 攻击方：`1..3`
- 防守方：`4..6`

不在 Adapter 内重新计算战斗。行动顺序、目标、伤害、恢复和状态全部以 `BattleResult.events` 为事实来源。

## 测试策略

### 协议单元测试

先写失败测试，验证：

1. 前锋对前锋距离为 1，大营对大营距离为 5。
2. 普通攻击优先选择敌方前锋。
3. 主动战法发动或进入准备后仍会普通攻击。
4. 犹豫只阻止主动战法，怯战只阻止普通攻击，混乱阻止整个行动。
5. 普攻伤害前后存在且只存在一对 `222/223`。
6. 技能伤害、恢复和状态位于 `213/214` 内。
7. 防守方普通攻击和技能事件也会生成动作段。
8. 开始与结束标记严格配对，不允许未闭合或交叉嵌套。

### 客户端队列模拟测试

在测试中模拟 `BattleAnimationData.SetRoundData` 的核心状态机：

- 收到 `222` 创建 `begin = 2` 的动作段。
- 收到 `213` 创建 `begin = 5` 的动作段。
- 段内 action 加入当前段。
- 收到 `223/214` 后关闭当前段。

断言生成结果至少包含：

- 攻击方的可播放动作段。
- 防守方的可播放动作段。
- 普攻伤害。
- 技能伤害或恢复。

### 全量验证

运行：

```bash
./gradlew test installDist --no-daemon -Dkotlin.compiler.execution.strategy=in-process
```

客户端联调时重新生成战报并打开详情，确认双方轮流行动、普通攻击和主动战法可见。

## 验收标准

- 战报详情不崩溃。
- 至少一场默认战斗中攻守双方都有可播放动作。
- 普通攻击能展示动作和兵力变化。
- 主动战法能展示施放以及对应效果。
- 动作顺序与 `BattleResult.events` 一致。
- 前锋、中军、大营的攻击距离和目标选择符合阵型位置。
- 主动战法不会吞掉同回合普通攻击。
- 混乱、犹豫、怯战分别具有独立语义。
- 所有自动化测试和安装包构建通过。
