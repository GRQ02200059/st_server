# 战斗系统一期重构设计

## 目标

以 `stzbBattleSimulator-main` 的可运行规则为行为参考，以客户端 CSV 和反编译代码为协议与配置依据，重构服务端战斗内核。保留现有客户端战报编码，不实现动画。

一期交付范围：

- 武将等级成长、自由加点、进阶、四大营、阵营组合和兵种加成。
- 被动阶段、准备回合、1–8 正式回合、速度与先手排序。
- 主动、指挥、被动、追击战法，准备、发动率、攻击距离和目标选择。
- 普攻、连击、追击。
- 混乱、犹豫、怯战、规避、洞察、持续伤害、恢复、属性变化和伤害增减。
- 移植参考项目中 1001–1032 共 32 个已实现战法。
- 所有事件继续通过 `BattleEvent` 转换为客户端现有战报。

## 架构

`BattleEngine` 只负责编排阶段和行动，不再直接承载各类战法特判。战斗规则拆为四个深模块：

1. `BattleFormationCalculator`：从武将配置和队伍上下文一次性计算初始属性及组合加成。
2. `BattleEffectState`：统一保存有来源、有类型、有持续时间的状态、属性层和伤害层。
3. `BattleActionResolver`：处理目标距离、普攻、连击、追击、伤害和恢复。
4. `LegacySkillCatalog`：将参考项目 1001–1032 的行为注册为 Kotlin 战法定义，由统一运行时调度。

`BattleEvent` 是规则内核与战报编码之间唯一的 seam。客户端编码器只消费事件，不参与规则判断。

## 数据规则

- 基础属性来自 `hero_table.csv`，按 `基础 + 成长 × (等级 - 1)` 计算。
- 加点和进阶作为显式 `BattleHeroSpec` 输入；缺省为 0，兼容现有调用。
- 四大营一期按参考项目对攻击、防御、谋略、速度各加 20。
- 阵营、兵种和称号组合优先读取配置；没有精确配置时不虚构数值。
- 士气影响战法发动率，采用参考项目公式：
  `rate × (1 + (morale - 100) / (100 + 0.5 × morale))`。
- 同类状态遵守强效果覆盖弱效果；不同来源和不同类别可按规则叠加。
- 战斗结束条件为任一方大营阵亡；八回合后按存活兵力判定胜负或平局。

## 阶段与行动

1. 战前初始化属性和队伍加成。
2. `-1` 被动阶段。
3. `0` 准备回合，执行指挥战法。
4. 每个正式回合：
   - 回合开始持续效果；
   - 先手优先、再按速度排序；
   - 行动前状态结算；
   - 主动战法；
   - 普攻；
   - 每次普攻后追击；
   - 连击触发第二次完整普攻及追击；
   - 行动后与回合末结算。

## 战法迁移

1001–1032 逐个迁移，保持参考项目的类型、目标、发动率、准备回合、持续时间和效果。共享行为必须使用统一效果原语，不在 `BattleEngine` 中添加战法 ID 分支。

## 测试

- 每个效果原语至少一个确定性单测。
- 每个战法至少一个发动用例；复杂战法另加未发动、覆盖或持续时间用例。
- 固定随机种子的三人队完整战斗测试，断言所有存活武将均行动、存在普攻和技能事件。
- 战报回归测试验证新事件仍能被现有客户端编码器完整输出。
- 最终运行 `./gradlew test installDist` 和 `git diff --check`。
